# Changelog

All notable changes to this project are documented in this file.

## [1.1.5] - 2026-06-09

### Added
- **Interactive HTML report.** New `--report <FILE.html>` writes a single self-contained page for exploring the called variants: a headline count with supporting tiles, the Sequence Ontology consequence distribution, an alignment-style variant matrix, a read-backed haplotype panel, and a virtualised, sortable table with a filter on every column (checkbox lists for the categorical fields, contains matches for the free-text ones, min/max ranges for Grantham and frequency) and a per-variant detail panel (HGVS `g.`/`c.`/`p.`, Grantham, DBS class, NMD, codons, event components, read support). The matrix is a small genome browser: samples down the side, real genomic coordinates across the top, coloured by alternate base, with scroll-to-zoom, drag-to-pan, a whole-contig strip you can drag across to select a range, a region box that takes `start-end`, `contig:start-end`, a coordinate or a gene name, density lanes (all calls, SNP, MNV, indel, HIGH impact and distinct samples, each its own chart with its own scale), and a gene track marking the extent of each gene's called sites. It orders samples by shared profile, marks positions called together on the same reads, and zooms down to the base letter; a cell is only ever an ALT call or "not called", since get_MNV output cannot tell a reference base from missing coverage. The haplotype panel ranks codon-level MNVs and phased complex indels by how many samples share them, with their phasing support; long-range phasing is never inferred. Filters drive the charts as well as the table, the current selection can be exported as TSV, and the masthead links to the repository and the documentation. The page embeds its data and loads nothing external, so it opens offline by double-clicking; repeated fields are dictionary-encoded to keep cohort-sized reports in the low megabytes. With `--sample all` one report covers every sample. For cohorts processed one sample per run, `--report-from a.MNV.tsv b.MNV.tsv ...` aggregates existing TSV outputs into one report without re-running the pipeline.
- **Sequence Ontology consequence terms and impact levels.** New `SO Term` and `Impact` TSV columns (and `SO` / `IMPACT` VCF INFO fields) annotate every variant with a standard SO term (`missense_variant`, `synonymous_variant`, `stop_gained`, `stop_lost`, `start_lost`, `frameshift_variant`, `inframe_insertion`/`inframe_deletion`, `intergenic_variant`, `coding_sequence_variant`) and a `HIGH`/`MODERATE`/`LOW`/`MODIFIER` impact, following SnpEff/VEP conventions.
- **Grantham distance for missense changes.** A new `Grantham` TSV column (and `GD` VCF INFO field) reports the Grantham (1974) distance of the combined amino-acid substitution together with its conservation category (e.g. `177 (radical)`), for genuine missense changes only.
- **MNV-vs-SNV consequence shift.** A new `MNV Consequence Shift` TSV column (and `MNVSHIFT` VCF INFO field) flags whether a combined MNV is `MNV-gained` (more severe than any single SNV alone, e.g. two individually-synonymous SNVs producing a non-synonymous residue, which per-SNV annotators miss), `MNV-masked` (a nonsense SNV rescued by its neighbour), or `Concordant`.
- **Doublet base substitution (DBS) class.** A new `DBS Class` TSV column (and `DBS` VCF INFO field) reports the COSMIC-style doublet class for an MNV of two adjacent single-base substitutions, e.g. `CC>TT`, reverse-complement collapsed so both strands map to one class. Enables tallying mutational signatures (UV `CC>TT`, APOBEC/ADAR dinucleotide contexts) directly from codon-level MNV calls.
- **MNV phasing (linkage) support.** With `--bam`, a new `MNV Phasing Support` TSV column (and `MNVPS` VCF INFO field) answers whether the substitutions in a codon sit on the same molecules, which is the difference between a codon-level MNV and two variants that happen to share a codon. Among the reads that observe *every* position of the codon and carry the least-supported constituent SNV, it reports the fraction that also carry the full haplotype. Near `1.0` is a genuine co-occurring haplotype; low values flag same-codon SNVs that largely fall on different molecules, which matters most for intra-host data. Only reads reaching across the whole codon are counted, on either side of the ratio: one that stops between two positions saw no evidence about the pair, so it neither supports nor dilutes the answer. The three states are distinct and mean different things: a number, `0.0000` when reads did span the codon and none carried both, and `-` when nothing could answer the question. A companion `MNV Phasing Reads` column (and `MNVPR` INFO field) reports how many reads the ratio rests on, so `1.0000` from three reads is not read as `1.0000` from three hundred.
- **Phase declared by the input caller is now read and reported.** Long-read pipelines (WhatsHap, HiPhase, Clair3) publish `GT` with `|` and a `PS` phase set, resolving exactly the question get_MNV asks about a codon MNV; get_MNV ignored it, so a codon the caller had already phased arrived unannotated. Both VCF parsers now read `GT` and `PS` for the selected sample, and a new `Declared Phase` TSV column (and `DPHASE` VCF INFO field) reports what the input claimed, as `cis:12345`. Only a `|`-separated genotype counts: a `/` genotype is the caller saying it did not resolve the phase, and reading it as phase would invent linkage the input never claimed. Only records sharing a phase set are compared, since two records phased in different sets say nothing about each other, and a record is matched to a row by both coordinate and base: a multiallelic site splits into one record per ALT and a genotype such as `2|0` places the second ALT on a haplotype and the first on none, so matching on the coordinate alone would hand one allele's claim to the other. The claim is reported beside the read evidence, never merged into it, and `|contradicted-by-reads` is appended where the BAM leaves it no room: a declared cis that not one spanning read carries whole, or a declared trans that every informative read carries. Those two extremes are facts rather than judgements, so no new threshold is introduced; anything in between is already reported as a ratio by `MNV Phasing Support`.
- **Codon-level linkage disequilibrium.** With `--bam`, new `Haplotype LD` and `Haplotype LD p` TSV columns (and `LD` / `LDP` VCF INFO fields) report `D'` between a codon's substitutions and the two-tailed Fisher exact p-value behind it, computed over the molecules that observe every position. A co-occurrence ratio, which is what every phasing metric here was until now, cannot separate a haplotype from an accident of frequency: two substitutions each present on 90% of molecules are found together on 81% of them by arithmetic alone, and the ratio reports `0.9000`, which reads as strong linkage. `D'` measures the excess over what the two frequencies predict, normalised by the most that excess could have been, so the same data gives `0.0000` at `p = 1`. The scale is symmetric and that matters: `+1` is one haplotype, `~0` is two variants that merely share a codon, and `-1` is mutual exclusion, both alleles present and never on one molecule, which in a haploid population is two competing lineages rather than one variant and is the read-level signature of a mixed infection. No per-variant annotator reports this, because none of them looks at which molecules carry what; get_MNV already had the 2x2 table of molecule counts and was throwing away everything except one ratio of it. It covers local indel haplotypes too, not only codon MNVs: the joint distribution those rows need is the one discovery already builds to decide which combinations exist, restricted to the variants each row carries. That matters because the read count and the linkage answer different questions, and an indel haplotype had only the count: five molecules carrying an insertion and a substitution together is a real combination, and `D'` of -0.17 at `p = 0.75` says it is about what two variants at 40% and 30% meet at by chance. With three or more variants the weakest pair decides, since the row claims one molecule carries all of them. The value is absent, not zero, when no molecule spans the codon or when an allele is on every molecule or none, which leaves nothing to correlate. Validated in `tests/phasing/` against a second derivation of `D'` and of the exact test written in the suite itself.
- **Read counting checked against `bcftools mpileup`** (`tests/pileup/`, new CI job). Every existing check on the read counting was written by the same hand as the code: the scenario expectations and the phasing suite's arithmetic both catch implementation error, and neither can catch a shared misunderstanding of what a read is worth, because both start from the same understanding. This suite hands the same BAM to a tool nobody here wrote and compares four numbers per site: depth against `FORMAT/DP`, allele support against `AD`, and the two strand arms against `ADF` and `ADR`. Those four are where this layer's defects have actually been; the strand-attribution bug fixed on this branch is a flat disagreement with `ADF`/`ADR` and would have been caught the day it was written. Both tools are given the same base-quality and mapping-quality floors and BAQ is disabled, so a difference cannot come from asking them different questions, and every comparison site sits between genes so no codon grouping stands in the way. Cases cover both strands, an allele on one strand only, mate pairs reading different sites, overlapping mates, and bases and reads below the floors. As in the differential suite, an explained difference is written down where it arises and an unexplained one fails the run: there is one, on overlapping mates, where bcftools keeps one mate and get_MNV keeps both, and the two conventions are both defensible. Pointed at the build before the strand fix it reports fifteen reverse molecules at a position no reverse read ever reached.
- **Read-level phasing validation** (`tests/phasing/`, new CI job). The synthetic truth suite validates the codon arithmetic but has no BAM, so nothing checked the other half of an MNV call. This suite builds alignments molecule by molecule, choosing which reads carry which variants, and checks that get_MNV recovers the mixture it was handed; every expectation is arithmetic on the molecule counts, never a number copied from a previous run. It sweeps five codon geometries (plus strand, minus strand, a codon split by an intron and spanned by a CIGAR `N`, all three positions of one codon, and the plus-strand codon sequenced as mate pairs that each reach only one of its ends) through all 21 mixtures from fully trans to fully cis, and adds the cases where the honest answer is not a number: reads that stop before the partner position, no spanning read at all, and a minority haplotype nested inside a major variant. It also checks `D'` and the exact test against 2x2 tables derived a second time in the suite. 120 mixtures, a few seconds. Pointed at the build before the phasing fix it reports 171 disagreements.
- **Nonsense-mediated decay (NMD) prediction.** A new `NMD Prediction` TSV column (and `NMD` VCF INFO field) applies the 50-nucleotide rule to premature stops in multi-exon transcripts: `NMD-triggering` when the premature stop is more than 50 nt upstream of the last exon-exon junction, `NMD-escaping` when it lies in the last exon or within 50 nt of that junction. Covers nonsense SNVs/MNVs and stop-gaining indels (frameshift and in-frame); single-exon transcripts have no junction and are left unannotated.
- **HGVS genomic and coding descriptors.** New `HGVS g.` and `HGVS c.` TSV columns (and `HGVSG` / `HGVSC` VCF INFO fields) complement the existing protein-level (`p.`) notation. Genomic descriptors cover every variant: `g.100A>G` for SNVs, the allele bracket `g.[28G>T;30T>A]` for MNVs, and `g.101_102del` / `g.100_101insTG` / `g.101delinsC` for indels. Coding descriptors cover substitutions (`c.30A>G`, `c.[28G>A;30T>C]`), numbered from the CDS start with coding-strand bases on both strands. Descriptors are not 3'-shifted and carry no reference-accession prefix; coding indel descriptors are not yet emitted.
- **Splice-site consequence terms.** Variants near an internal exon-exon junction of a multi-exon transcript now receive the standard Sequence Ontology splice terms in the `SO Term` / `Impact` columns (and `SO` / `IMPACT` VCF INFO fields): `splice_donor_variant` / `splice_acceptor_variant` for the two essential intronic bases at each intron end (`HIGH`), and `splice_region_variant` for the exon's last 3 bases or the intron's 3rd-8th bases (`LOW`). Intronic splice variants, previously reported as intergenic, are now associated with their gene; an exonic coding change near a junction is combined, e.g. `missense_variant&splice_region_variant`, keeping the more severe impact. Single-exon transcripts (prokaryotes, most viruses) have no junction and are unaffected, as are CDS models whose segments abut or overlap in a ribosomal-slippage join rather than being spliced.
- **Synthetic ground-truth validation** (`tests/truth/`, new CI job). The differential suite compares against tools we did not write, which is the stronger check, but it cannot validate the one thing get_MNV exists for: no per-variant annotator combines two SNVs in a codon the way get_MNV does, so on exactly those calls the oracles disagree by design. This suite builds a genome with four genes (plus and minus strand, single-exon and spliced) and derives the expected answer by a different route from get_MNV's: mutate the genome, re-extract the CDS, translate, compare proteins, using a codon table written out in the suite. It covers every single substitution at every position of every codon, every pair in a codon, and the triple, plus 2130 indels (deletions and insertions of 1 to 3 bases at every position of every exon, with the indel applied in CDS coordinate space): about 3700 cases, each checked on gene, amino-acid change, change type, both codons and the HGVS `c.` descriptor, in about twelve seconds. It is a second implementation by the same hand, so it catches implementation mistakes rather than a shared misunderstanding, and the consequence labels follow the documented convention; the amino acid, the codons and the CDS coordinate are the independent parts. Pointed at the build before the codon-orientation fix it reports 240 disagreements, all on the minus-strand genes.
- **Differential annotation suite** (`tests/differential/`, new CI job). get_MNV's own tests can only check that it produces what we wrote down as expected; when the expectation is wrong the test goes green and the tool stays wrong, which is how a ribosomal-slippage CDS join came to be given splice sites. The suite compares get_MNV against annotators we did not write: `bcftools csq` run live on small committed fixtures (a slippage join and, as the positive control, a genuinely spliced transcript), both tools reading the same reference and the same GFF3; and SnpEff 4.1l through the `ANN=` fields already present in the bundled *M. tuberculosis* VCF, where 923 of 950 real calls agree. The rule is not that the tools must match, because get_MNV disagrees on purpose: every difference is matched against `baseline.tsv`, a versioned list of accepted differences with the reason written down, and CI fails only on a difference nobody has explained. `GET_MNV_BIN` points the suite at another build, which is how it was confirmed to still fail on the commit before the slippage fix.
- Added regression coverage for phased MNV-plus-indel haplotypes, verifying that codon MNV rows overlapping an indel are flagged as `Indel overlap` while BAM-supported combined events are emitted as exact `complex_indel` rows.
- Added an indel/MNV semantics note documenting caller compatibility, boundary rules, current limits, and how exact complex haplotypes are represented.
- Added transcript-aware regression coverage for exon-junction MNV codons and restored-frame indel contexts in multi-exon CDS models.

### Changed
- Mutation testing now covers the read counting, which was the least-tested part of the tool and the part where every recent defect lived. It was excluded before for a practical reason: the counting was reachable only through an indexed BAM, so it had three unit tests across 1450 lines, and mutating code no unit test reaches only reports that no unit test reaches it. The counting core now takes its observations through a test constructor instead of a BAM, and fourteen unit tests pin what a molecule is: mates merged, mates disagreeing, strand per position, the spanning rule, the quality floor and its boundary, and the joint distribution the linkage statistics read. The first run over the new scope left 40 mutants alive out of 188; the tests written to answer them brought that to 14 with 140 caught. Two groups were worth having: the linkage arithmetic, whose original tests used symmetric tables and degenerate answers that survive a changed operator, and the cis/trans rule deciding whether an upstream indel shifts a downstream codon, which had no test of its own so neither of its thresholds was pinned. The fourteen that remain are named in the config: eleven need a `bam::Record` to reach and belong to the suites that cannot run per mutant, two are equivalent, and one is a tie-break between two equally right answers. Reading a BAM stays out of scope, since that is I/O covered by the suites that need samtools and cannot run once per mutant.
- The mutation-testing workflow no longer runs on a schedule. It is `workflow_dispatch` only, like every other manual job here.
- A local haplotype row is now counted by the molecules that *are* it, not by the molecules that match its allele. Reading combinations off the molecules fixed which haplotypes get proposed, but the count on each row still came from the exact-allele count, which matches over that combination's own reference span: a molecule carrying that combination *and more* matches too, when the extra variant falls outside the span. So a genuine two-variant haplotype sitting inside a real three-variant species was reported with the species' entire read count at 100% frequency, which is the same double-counting the enumerate-and-test scheme was replaced to remove, surviving one step further along. Discovery already knows how many molecules are exactly each combination, over every variant of the window; it now carries the strand split too, and the row takes its support from there. The exact count keeps the job it can do: confirming the allele is reproducible at all, which is the CIGAR-aware check that matters for net-neutral insertion-plus-deletion combinations, and supplying the window depth.
- A multi-agent audit of the haplotype and read-counting layer raised 22 findings, 17 of which survived adversarial refutation and are fixed here. Grouped by what went wrong:
  - **Strand was tracked per molecule instead of per position.** A fragment's two mates usually land hundreds of bases apart, and the strand flags were OR-ed across every record of the fragment and then applied to each position, so a variant read only by the reverse mate was credited to the forward arm as well. Forward depth equalled reverse depth almost everywhere, which left `--min-snp-strand`, `--min-mnv-strand` and the strand-bias test unable to reject anything in paired-end data. Strand now travels with each observation. For a multi-position row an arm counts only when that strand read every position, since a haplotype pieced together from a forward mate and a reverse mate was confirmed by neither strand alone.
  - **A whole run aborted on a multi-base substitution outside a gene.** `AC>GT` in an intergenic region with `--bam` reached the SNP row builder without read counts and failed with "Missing SNP read counts". Rows that were never read-counted now take the placeholder layout, in the TSV and the VCF alike.
  - **Three copies of "how much must a read see".** An insertion lives between two reference bases, so a read stopping on the anchor has seen nothing of the junction; a deletion needs the base past its end, because inside its own REF span a longer deletion is indistinguishable from the declared one. The exact counting, the local-haplotype discovery and the indel-versus-SNV phasing each decided this separately and disagreed, and the worst combination silently cancelled real support: a mate ending on an insertion's anchor was read as "reference here" and stripped the ALT support its partner had provided. One `observation_ref_len` now answers it for all three, and a read whose deletion runs past the allele is no longer exact support for it.
  - **Mate disagreement was resolved by OR in two places.** The substitution counting drops a position where the mates read different bases; the local-haplotype discovery and the trans test instead let whichever mate saw the ALT win. All three now agree that a contradicted observation is no observation.
  - **Symbolic SV alleles were always judged trans.** `<DEL>` has no sequence for a read to reproduce, so every spanning molecule scored as informative-and-not-cis, which reads as proof of trans and cancelled the frameshift the SV should propagate. The reads cannot answer for a symbolic allele, and the pair is now left out rather than answered wrongly.
  - **Read phasing was keyed on position without the allele.** At a multi-allelic site the last ALT processed overwrote the other's evidence and then decided its codon.
  - **A declared-phase claim spoke for alleles nobody had phased.** One comparable pair was enough to publish the whole row as `cis`, even when another of its positions sat in a different phase set or carried no genotype at all. Every position must now carry a claim in one phase set. A no-call (`.`) slot is also no longer read as "not this ALT": it might be holding it, so two half-called records can no longer be declared trans.
  - **Unnamed reads collapsed into one molecule.** With SAM `QNAME` `*` the fallback key was only the segment flags and the start position, so every unnamed read starting there became a single molecule and the depth fell to one.
  - **The exact test was quadratic.** `ln(n!)` was recomputed term by term inside the Fisher loop, which is fine for a handful of reads and not at intra-host depths. It is tabulated once per call, which also speeds up the existing strand-bias test.
- Added mutation testing (`cargo mutants`, `.cargo/mutants.toml`, a manually-run advisory CI job). It changes the source (flips a comparison, replaces a function body with a default) and reports whether the suite notices; a surviving mutant is logic no test distinguishes. Its first run showed that the indel and frameshift-propagation conditionals of the **spliced-transcript** path were almost entirely undistinguished: the scenario suite covers that logic on single-feature prokaryotic genes, which take the genomic-coordinate path, and the spliced path has its own copy. Five tests now cover it (upstream frameshift reaching the next exon, an in-frame upstream indel not shifting anything, no propagation backwards, an indel marking only the codon it overlaps, and the frequency gate), and they kill five of the six mutants that survived there; the sixth is equivalent, since only `% 3 != 0` is read and that cannot tell a sign flip apart. It also found a redundant guard in the stop-count comparison, now removed. The job never fails the build.
### Changed
- A paired-end fragment now counts as one molecule instead of two reads. A fragment is a single DNA molecule sequenced from both ends, and get_MNV was counting its two mates as two independent observations. That did two kinds of damage. Wherever the mates overlap, the same molecule was counted twice, inflating depth and making a frequency look supported by twice the material actually there. And a variant on each mate was treated as unrelated when it is in fact proof the two are on the same molecule: a codon split by an intron can be unanswerable read by read (`MNV Phasing Support` of `-`) and settled by the pair. Read counting, local haplotype discovery, the indel/complex event counts and the indel-versus-SNV trans test now work per molecule; where the mates overlap and disagree about a base, one of them is wrong and there is no telling which, so the molecule is treated as not having observed that position. Strand travels with each observation rather than with the molecule: where both mates read a position and agree, it counts on both strands, and where only one mate reached it, only that strand counts. Crediting a fragment's strands to every position it touches made forward depth equal reverse depth almost everywhere, which reads as no strand bias anywhere. The same view applies to the indel and complex-event counts: a molecule whose mates read different alleles over the locus does not support the call, where before a single mate carrying an alignment artefact was enough to credit the whole molecule, and mate overlap is exactly where indel realignment artefacts appear. Single-end data is unaffected. `--count-mates-separately` restores the per-record behaviour for comparability with earlier output. Exact event counting still needs one contiguous observation, so a local haplotype whose variants fall on different mates is discovered but cannot be supported, and the support threshold drops it rather than reporting it with no evidence.
- The read-level phasing behind frameshift suppression is now reported instead of only acted on. When a BAM is given, get_MNV already asks whether an upstream indel and a downstream codon share molecules, and declines to propagate the frame shift when they do not; the numbers behind that decision were computed and thrown away. A new `Frameshift Phasing` TSV column (and `FSPH` VCF INFO field) carries them as `trans:1234:0/18`: the verdict, the indel's position, and the reads in cis out of the reads able to answer. Without it a codon that is not labelled frameshifted looked identical whether the reads had proved the indel sits on other molecules or nobody had asked. The cis/trans thresholds stay with the read counting that applies them, so the annotation layer reports a judged answer rather than re-deriving the rule from the counts.
- `--phased-indel-min-reads` now defaults to `2` (was `1`). Since haplotypes are read off the molecules, a single read carrying a sequencing error at a called position mints a combination of its own, and one read was enough to publish it as a haplotype row. Two reads is the least that means more than one molecule. Set `1` to emit every combination any read shows.
- Local haplotypes are now read off the molecules instead of enumerated and checked. Nearby variants were grouped into a window, every subset of that window was proposed as a candidate haplotype, and each was put to the BAM one query at a time. Two things followed. A subset was accepted whenever some read matched its compound allele over that subset's own span, so a single molecule carrying A, B and C also answered yes for A-plus-B and for B-plus-C, and one species was reported as three rows, each claiming the full read count and 100% frequency. And because `2^n` candidates is not a workable number, windows of more than eight linked variants fell back to pairs and the full set, silently omitting genuine intermediate haplotypes. get_MNV now asks the reads spanning the window which combinations they carry and reports those, with the count of molecules behind each. A combination no molecule is does not appear; two combinations that genuinely coexist both appear with their own counts, which the old scheme could not tell apart from one molecule carrying everything. The variant cap is gone, since reading costs one query per window rather than one per candidate; a bound of 64 reported combinations per window remains as a guard against a noisy pile-up, and says in the log what it set aside. A molecule that stops inside the window is counted separately and used for nothing, because a partial molecule is not a haplotype. Each candidate is judged on its own reference span, and for an insertion that span reaches one base past the anchor: an insertion lives between two reference bases, so a read ending on the anchor has seen the anchor and nothing of the junction, and recording it as evidence that the insertion is absent minted a subset haplotype no molecule had shown.
- Where a transcript's introns are is now derived once, by `Gene::introns`, instead of being recomputed by splice-site classification, the intronic-position test and the NMD junction independently. Three copies of the same geometry are three chances to disagree about it, which is the shape of the bug that gave a ribosomal-slippage join splice sites. The derivation yields nothing for an unspliced transcript, so that case is handled in one place too.
- The GFF CDS model now rejects and reports annotation it cannot assemble. A transcript whose CDS rows disagree about the strand kept whichever strand came first and sorted the segments by it, silently producing a nonsense reading frame; those rows are now left as per-feature annotations with a warning. A CDS row listed twice (concatenated annotation files, a repeated segment) counted its bases twice in the spliced CDS and shifted every codon after it; repeats are now dropped with a warning. A run that builds multi-segment models logs how many came out spliced and how many are one continuous reading frame, so the model get_MNV understood is visible rather than assumed.
### Changed
- Added property-based tests (`proptest`) over generated inputs. The headline invariant is strand symmetry: annotating a variant on a plus-strand gene must give the same amino-acid consequence, change type and codons as annotating the mirrored variant on the reverse-complemented genome, where the same gene sits on the minus strand. The two runs describe the same molecule, so every protein-level answer has to match, and no hand-written example pins that down across gene lengths, offsets and positions at once; it found the codon-orientation bug above on its first run. Codon-bounds invariants are now checked over generated gene shapes, strands and phases rather than one hard-coded feature.
### Changed
- Gene fixtures in the test suite are now built from GFF text through the real parser (`test_support`), not from hand-written `Gene` struct literals. A literal can describe a gene model no annotation file would produce, and then the test agrees with the code about something untrue: a helper named `two_exon_gene` built exons that abutted, with no intron between them, so every test meant to cover splicing was quietly asserting the behaviour of an unspliced transcript, and they passed while confirming a bug. `spliced_gene` and `joined_gene` now refuse segments that do not match the transcript the test claims to be about, so the fixture name carries the claim and the helper enforces it. 40 of the 46 literals are gone; the survivors are two parser constructors, one raw-record builder used to test the parser itself, a benchmark, and two deliberately impossible models, each marked as such. Parsing was split into a reader-based entry point so annotation can be parsed from memory. Output is unchanged: the differential suite reports the same agreements before and after.
- Consequence classification now lives in one module (`variants::consequence`) instead of two independent implementations. Substitutions were classified by `determine_change_type`, which parsed a formatted string such as `M1T`, while indels had their own rules over the reference and alternate translations; the initiator rule existed on the substitution side only, which is how an in-frame indel that deleted the start codon came to be reported at `MODERATE` impact. Both paths now call the same rules, a test holds them to the same answer for every residue at protein position 1, and the codon paths pass the residues directly instead of formatting a string for the classifier to parse back out (feeding it the three-letter IUPAC form used to misclassify the change). Output is unchanged: the differential suite reports the same 923 of 950 agreements on the real dataset before and after.
- `--chrom` now restricts FASTA loading: when a single contig is requested, only that contig is read and IUPAC-validated instead of the whole genome, cutting peak memory for large (e.g. eukaryotic) references. A missing requested contig now fails with a clear "not found in FASTA" error.
- SNVs/MNVs that alter the initiator Met (protein position 1) are now reported with Change Type `Start lost` instead of `Non-synonymous`, matching standard annotators. The reported amino-acid change was already correct; only the classification label changes. `Met1` → stop is still `Stop gained`.
- Added a tuned `[profile.release]` (thin LTO, single codegen unit) and wrapped plain (non-BGZF) VCF output in a buffered writer with an explicit flush, for faster production builds and record emission.
- Pinned `sha2` to the stable `0.10` line (previously a `0.11` pre-release), removing a duplicate hashing dependency stack from the resolved graph.
- `get_mnv_variants_for_gene` and `get_mnv_variants_for_transcript` now build a list of mutually-exclusive codon interpretations per codon start. Multi-allelic positions expand the interpretation set as a Cartesian product, deduplicated by `(position, alt)` keys, so a codon that contains N independent alts emits N output rows.
- Bumped project, GUI, citation, README, and frontend metadata to version 1.1.5.
- Updated the Tauri desktop dependency set to the 2.11 patch line, including `tauri` 2.11.2 and `tauri-plugin-dialog` 2.7.1.
- Updated frontend lockfile dependencies, including `postcss` 8.5.10.
- Added allele-level event decomposition for `snp`, `mnv`, `insertion`, `deletion`, `delins`, `complex_indel`, and symbolic alleles so length-changing events that also contain SNV/MNV components are represented as a single local haplotype event.
- Expanded phased local haplotype discovery from indel-plus-SNV pairs to bounded multi-event windows, allowing supported combinations such as insertion-plus-deletion haplotypes to be emitted as exact `complex_indel` rows.
- iVar TSV inputs now keep insertion and deletion rows by converting `+SEQ` and `-SEQ` alleles into VCF-compatible anchored `REF/ALT` alleles using the FASTA reference.
- TSV and VCF outputs now include canonical event class/component annotations plus exact BAM-derived event support metrics for indel/complex alleles.
- The desktop BAM viewer now renders insertion-aware interbase columns, so inserted bases are shown between reference positions with matching coverage, ruler, reference, and read-pileup alignment instead of being hidden inside the anchor base.
- When a BAM is provided, nearby SNV/MNV rows that phase with an indel on the same reads are now emitted as an additional exact `complex_indel` haplotype row, preserving the original rows while reporting the combined `REF/ALT`, protein effect, and event support.
- GFF/GTF `CDS` rows with `transcript_id` or `Parent` are now collapsed into spliced transcript CDS models, so codon grouping, MNV amino-acid effects, and indel frameshift context are evaluated against the full coding sequence instead of isolated exon rows.
- `--frameshift-min-freq` now defaults to `0.5` instead of `0.0`: an upstream indel only shifts the reading frame of downstream SNV/MNV codons when it is the consensus (majority) allele, so a high-frequency downstream substitution is no longer relabelled frameshifted because of a low-frequency upstream indel that is almost certainly on a different molecule (intra-host data). Indels without a known frequency still propagate. Pass `--frameshift-min-freq 0.0` for the previous behaviour.
- Frameshift propagation is now **read-phased** when a BAM is provided: for an upstream indel and a downstream SNV within a read's reach, reads spanning both loci are inspected, and the frame shift is not propagated to that codon when the reads carrying the SNV overwhelmingly lack the indel (the two are in trans, on different molecules). This is a conservative, suppression-only refinement on top of the frequency gate (it never adds propagation the gate would not), and applies only where reads span both loci; beyond a read's reach the frequency gate still governs.
- Indel locus depth (the `EDP`/`EFREQ` denominator) is now counted from reads observing the anchor base by default, removing the depth under-counting and `EFREQ` bias for multi-base deletions. Pass `--legacy-indel-depth` to restrict the denominator to reads that fully span the REF allele.

### Changed
- **An insertion written against the base after it is re-anchored on entry.** VCF allows `31 G>AAAG` for the same `AAA` that `30 T>TAAA` describes, but that spelling puts the anchor before the record's own POS, and everything in get_MNV that observes an allele reads forward from POS: the exact indel counter and local haplotype discovery could not see the junction, so such a record reported zero supporting reads over a full depth and vanished from its own haplotype. Rather than teach every observer to reach backwards, the record is rewritten once, when the contig is loaded, into the spelling the rest of the pipeline already handles. The run says how many records it moved, and their reported POS/REF/ALT is the re-anchored form.

### Fixed
- **The report's variant table no longer paints fewer rows than it says it is showing.** Filtering while the table was scrolled down left rows blank and unreachable, often all of them, because `render()` shrinks the scroll spacer and repaints in the same tick, before the browser has clamped `scrollTop` to the shorter content, and once the filtered table stopped overflowing no scroll event arrived to correct it. Meanwhile the report's own "Export filtered TSV" wrote the full result, so one report disagreed with itself. The first visible row is now clamped to what the viewport can show, and a new result set starts at its top.
- **The report no longer counts `intergenic` as a gene.** It is the placeholder written in the Gene column for a variant outside every annotated gene, so the "Genes with a call" tile claimed one more gene than the same run's log and summary JSON, and the variant matrix drew a gene bar for it across the whole contig.
- **`HGVS g.` no longer uses the single-nucleotide `>` form for a multi-base allele.** A fallback row (intergenic, intron, splice site, or a position inside a gene that could not be given a codon) carries the record's whole REF and ALT, so a left-padded record came out as `g.1250AA>AT`: not a valid descriptor, naming a base that did not change, at a coordinate where nothing happened, and contradicting the row's own `Event Components`. Such a row is now described by the bases that actually differ.

### Fixed
- **A multi-base substitution outside a CDS is counted.** The intergenic, intron and splice path selected only `SNP` and `INDEL` rows, so an `MNV` row there reached no counter at all: it went out with no read support, and a threshold then read the absent counts as zero and deleted the row, or the run aborted with `[E000] Missing SNP read counts`. Whether a variant carried by most reads survived depended on where the gene boundaries happened to fall. Such rows now carry one entry per base that changes, the same shape the gene path builds, and are counted through the same window cache.
- **A base shared by two overlapping CDS rows is annotated in both codons it occupies.** In a ribosomal-slippage join, the `join(a..b, b..c)` shape this model supports for ORF1ab and its kin, the ribosome reads the shared base twice, so it sits at two offsets of the spliced coding sequence. Only the first was used, leaving the second codon holding the reference base: on the fixture built for this, a substitution reported one synonymous row and silently omitted the stop-loss in the codon after it. The indel path already walked every segment; substitutions now do the same.

### Fixed
- **A left-padded substitution outside a gene is counted at the base that changes.** A record such as `350 AA>AG` changes base 351, but the intergenic, intron and splice path counted at the record's POS using the raw ALT, whose first character is the padding base. That base is the reference, so every read scored as support: the row reported full frequency for a change most reads did not carry, while the same record under a covering gene reported the truth, and the run's own `COMP` and `HGVSG` named the position it had not counted at. These rows now take their positions and alleles from the decomposed components, as the gene path always did.
- **An insertion re-anchored onto an occupied coordinate no longer disappears.** Whether the gene path had produced a row for a record was decided by looking for its coordinate among the rows produced, so once re-anchoring moved an insertion onto a position a substitution already occupied, the insertion was judged already annotated and never emitted: two records in, one row out, silently. The question is now asked about the event a record describes rather than the coordinate it sits at.

### Fixed
- **A reference call is no longer annotated as a variant.** A record whose ALT repeats its REF describes no change, but it reached the annotator with nothing to decompose and came out as a row attributed to `intergenic` from inside a gene, typed `INDEL`, and carrying an `intergenic_variant` consequence: three claims about something that is not a variant. Callers do emit such rows into a variants file, so refusing the whole run would be unhelpful; they are skipped and the count is reported.

### Fixed
- **A record whose POS base does not change no longer produces two rows.** `28 GC>GA` changes base 29 and is annotated there, but the check for "did the gene path produce a row for this record" compared the record's own POS against the positions that did, so the record was judged unannotated and a second, contradictory row was emitted for it: one row said `g.29C>A` and the other `g.28GC>GA` for the same change. The check now considers every position the record could have produced. Introduced by the partial-codon fix earlier in this release.

### Fixed
- **A read marked as failing vendor QC is no longer counted as evidence.** Duplicate, secondary and supplementary records were excluded everywhere reads are counted, but the QC-fail flag (`0x200`) was not, so such reads inflated support, depth, frequency and everything downstream of them. `samtools mpileup` excludes it by default, which means get_MNV disagreed with the very oracle its own test suite compares against: on a BAM where half the reads carry the flag, mpileup reported a depth of 10 and get_MNV reported 20. The suite never caught it because none of its alignments carried the flag; a scenario now covers all four flags at once.

### Fixed
- **A substitution in a trailing partial codon is no longer dropped from every output.** When a feature's length is not a multiple of three, the gene path cannot build a codon around its last position and skipped the variant; the intergenic fallback then treated it as covered because a gene overlapped it, so the record vanished from the TSV, the VCF and the summary with no warning and exit 0. Sixty-four of the four thousand genes in the bundled annotation have such a length. Coverage is now decided by whether a row was actually produced, and a position inside a gene that could not be given a codon is reported against that gene as `coding_sequence_variant` with an unknown amino-acid effect.
- **`--exclude-intergenic` no longer deletes variants that are inside a gene.** The flag gated the whole fallback block, so splice-site and intron variants, which get_MNV attributes to a named gene and does not count as intergenic, disappeared with it: a HIGH-impact `splice_donor_variant` was removed by a flag documented as excluding "variants outside annotated genes". Only variants outside every feature are excluded now.
- **The output VCF is written in coordinate order.** A multi-position variant emits one record per constituent position, so a variant sitting between them was written after them and the file came out unsorted. `tabix` refused it, and because indexing runs after the VCF is already on disk, `--index-vcf-gz` aborted the run at that point and the BCF, the summary JSON, the manifest and the report were silently never written. Records are now buffered per contig and flushed in order.
- **An iVar indel row is checked against the FASTA like every other row.** The indel branches took the anchor base from the reference and never looked at the TSV's own `REF` column, so a FASTA that did not belong to the iVar run was rejected on a substitution row and silently accepted on an indel row of the same file, which then annotated against a reference the caller never saw. All three row types now fail the same way.
- **A CDS row with a multi-valued `Parent` belongs to every transcript it names.** GFF3 defines `Parent` as a comma-separated list, but the raw value was used as the transcript id, inventing a transcript literally called `t1,t2` and removing that exon from both real ones. A variant in another exon was then translated against a shortened coding sequence and reported the wrong reference codon, with the only warning naming the invented transcript.
- **Fisher exact p-values below roughly 1e-12 are computed rather than floored.** The "at least as extreme as observed" test used an absolute tolerance, so once the observed probability fell under it every candidate table qualified: a 30/0/0/30 split reported 1.5e-14 where the answer is 1.7e-17, and the ordering the strand-bias filter depends on could invert, tagging a weaker bias while passing a stronger one. The comparison is relative now, and the values are checked against scipy.

### Fixed
- **An insertion written against the base after it is no longer placed on the wrong side of that base.** VCF allows both spellings, and `29 C>CA` and `30 T>AT` describe the same inserted `A` between those two bases. The anchor was clamped into the record's own span, so the right-anchored spelling reported `INS:30:+A` instead of `INS:29:+A`, and the two spellings of one event annotated as two different frameshifts: `Ala11Cysfs` against `Ala11Serfs`. The anchor is now the base the insertion follows even when that base lies before the record's span. Found by a property holding that the published `Event Components` must rebuild the ALT allele they came from.

### Fixed
- **An indel outside every annotated feature keeps its read support.** The intergenic counter only understood single-position substitutions, so an indel there reached no counter at all and the row went out asserting `Event Reads = 0` at `Event Depth = 0` for an allele every read carried; the VCF omitted `ER`/`EDP`/`EFREQ` for the same allele in the same run, so the two outputs disagreed about whether anything was known. Such indels are now counted one at a time with the same exact-event counter used inside genes, and they are filtered on that support like any other row rather than being dropped outright whenever an MNV threshold is active.
- **`--normalize-alleles` no longer re-anchors an indel and destroys its support.** Trimming the shared suffix is the canonical first step for a substitution, but on a length-changing allele it can move the event: `29 CT>CTGCT` became `29 C>CTGC`, the same insertion at a different placement inside a repeat, which no longer matched the CIGAR the aligner used. A row with 20 of 20 supporting reads was reported at 0, with a warning telling the user to left-align their input, when it was the flag that had moved it. The trim now has to leave the event where it was: the canonical suffix-then-prefix form is used when it does, the prefix alone when the suffix step is what moved it, and the allele is left untouched when neither is safe. So `29 CT>CTGCT` trims to `30 T>TGCT` and `5 CG>CTG` still reaches its minimal `5 C>CT`. A property test holds the invariant over generated alleles; it is what caught the first attempt at this fix, which moved `5 CG>CTG` to `6 G>TG`.
- **`--run-manifest` records output checksums under `--sample all`.** That mode builds its own payload and listed the per-sample output paths with no checksum beside them, while the flag's own description promises them. Each sample entry now carries the SHA-256 of the files it wrote.

### Changed
- **The frameshift gate now weighs the frequency the reads give an indel, not the one the caller declared.** `--frameshift-min-freq` consulted `AF` from the input VCF alone, so on a VCF that writes no `AF` (VarScan-style output, including this repository's own example data) it passed every upstream indel at every threshold and the flag was inert exactly where read evidence existed. With `--bam` the gate now uses the frequency get_MNV counts itself, the same number it publishes as `EFREQ`; the declared `AF` remains the fallback when the reads were not consulted (no BAM, a dry run, or a symbolic ALT no read can reproduce), and an indel with no frequency from either source still propagates. The two scenarios covering this gate declared `AF=0.20` while their BAM carried the indel on 20 of 20 reads, so they never exercised the disagreement; their alignments now hold the indel on 4 of 20, and a new scenario covers a VCF with no `AF` at all.

### Fixed
- **A multi-base substitution inside a gene but outside every codon no longer aborts the run.** An intron, splice-region or non-coding-transcript allele is never read-counted, so its depth is absent even with `--bam`; the VCF writer demanded it and failed the whole run with `[E000] Missing total read depth`, writing no output files at all and losing every other variant in the file. It now keys on whether the counts exist rather than on whether a BAM was supplied, and emits the record the way the no-BAM path does. This is the VCF twin of the same guard already in the TSV writer.
- **`--report` no longer tells you to do something impossible.** The error, `--help` and the docs all said to add `--both` to a `--convert` run, but clap declares the two mutually exclusive, so following that advice always failed. They now say to use `--both` instead of `--convert`.
- **Documentation corrections found by running the binary against its own promises**: `--min-strand-bias-p` is VCF-only and never removes a TSV row; `--convert` writes the VCF *instead* of the TSV rather than in addition to it; and `--sample all` writes `<input_name>.sample_<SAMPLE>.MNV.tsv`, a naming pattern that appeared nowhere.

### Added
- **A run now warns when an MNV threshold cannot remove anything.** A codon-level row survives if *either* its individual SNVs or its haplotype clears its bar, so while the SNP thresholds sit at their default of `0` the SNP side passes for every row and `--mnv 5` on its own removes nothing at all. That is deliberate, and it was silent: the run looked filtered and was not. It now says so, naming the flags to raise, and pointing out that the MNV thresholds still reach pure MNV, indel and intergenic rows. No filtering behaviour changed.

### Fixed
- **A `--bam` run no longer drops VCF records the TSV keeps.** Any allele whose recomputed support was zero was skipped before the filter gate could weigh it, so adding a BAM made the VCF *lose* calls: on the bundled example, 9 of the 10 codon-level loci vanished from the VCF while all 10 stayed in the TSV, and `--emit-filtered` could not bring them back because the record never reached the code that tags filtered rows. Zero supporting reads is what a BAM that does not reach a locus reports, which is ordinary for a targeted panel or a subset alignment, so it is the absence of evidence and not a failed threshold. Those alleles now flow through the same gate as everything else: with no threshold set they are emitted with their zero counts, exactly as a run without a BAM emits them, and under a threshold they are skipped, or written with a `LowSupport` tag when `--emit-filtered` asks to see what was dropped. This restores the behaviour the documentation already described.

### Fixed
- The per-SNV columns of a minus-strand MNV are now emitted in ascending genomic order on both annotation paths. The spliced-transcript path listed them in transcript order (descending on the minus strand) while the genomic-coordinate path used ascending, so the same variant came out with `Positions` reversed depending on whether the annotation was a TSV or a GFF transcript, and the transcript path contradicted the `HGVS g.` descriptor on its own row, which is always ascending. `Positions` is a coordinate column; the parallel per-SNV columns follow it. The amino-acid calls were identical throughout, and the order is now documented.
### Fixed
- **Scientific**: a read that skips an intron (CIGAR `N`) is no longer counted as carrying a deletion of those bases. Both `N` and `D` advance the reference without consuming query bases, and the observed allele was reconstructed from the CIGAR treating them alike, so a spliced read looked exactly like one carrying the deletion allele: a 2 bp deletion covered only by an intron-skipping read was reported with `Event Reads = 1` and `Event Frequency = 1.0000`, perfect support from a read that does not carry it. A skipped position is now simply not observed by that read, which is what it is. `D` still means the base is absent from the molecule. Single-base lookups already treated the two alike correctly, because there both mean "no base here".
### Fixed
- **Scientific**: the codon columns (`Reference Codon`, `SNP Codon`, `MNV Codon`) are now reported in the transcript's own orientation on every annotation path. The genomic-coordinate path emitted the genomic-strand bases for a minus-strand gene, so a row could read `Reference Codon = CAT` beside `AA Changes = Met1`, a codon that does not translate to the amino acid next to it, while the spliced-transcript path and the `HGVS c.` column on the same row already used coding-strand bases. The same gene and variant therefore produced different codons depending on whether the annotation was a TSV/single-CDS file or a multi-exon GFF. Amino-acid calls, change types and impacts are unaffected. Found by the new strand-symmetry property test.
### Fixed
- **Scientific**: the TSV annotation format gained an optional sixth column for the feature biotype, so non-coding RNA genes are no longer translated as though they were proteins. The format carried no biotype at all, so every feature was assumed protein-coding and a variant in an RNA gene came back with an invented amino-acid change at `MODERATE` impact (`mcr11_RVnc0013` in the bundled *M. tuberculosis* annotation reported `Asp26Gly`). A feature declared non-coding is now reported against its gene as `non_coding_transcript_exon_variant` (`MODIFIER`) with no amino-acid change. Four- and five-column files keep their existing behaviour, and an unrecognised biotype is rejected with an error listing the accepted vocabulary rather than guessed. GFF/GTF input is unaffected, because it selects `CDS` features. Found by the differential suite.
- **Scientific**: a variant inside a real intron is now reported as `intron_variant` (`MODIFIER`) against the gene it sits in, instead of `intergenic_variant`. A position deep in an intron falls outside every CDS segment, and get_MNV had no intronic concept at all, so it was called intergenic: correct for prokaryotes, wrong for the spliced transcripts get_MNV now supports, and it dropped the gene from the annotation entirely. Splice sites keep their more specific terms, and an unspliced transcript (a single CDS segment, or a ribosomal-slippage join) has no intronic positions, so prokaryotic annotation is unchanged. Found by the new differential suite on its first run.
- **Scientific**: an in-frame indel that destroys the initiator codon is now reported as `Start lost` / `start_lost` (`HIGH`) instead of the generic `In-frame Indel` / `inframe_deletion`-`inframe_insertion` (`MODERATE`). Substitutions already reported this, so the same consequence carried two different impacts depending on the variant class, and a deletion of the start codon was invisible to anyone filtering on `HIGH`. The amino-acid notation is unchanged (`Met1del`, `Met1delinsArgVal`). Frameshifts keep the frameshift label, which is already `HIGH`, and a CDS model that does not begin at an initiator (partial or phase-shifted) is left alone.
- The report's per-column categorical filters now use a prototype-less lookup, so a value named `constructor`, `toString` or similar can no longer match an inherited property and pass a filter it was not selected in.
- **Scientific**: consecutive CDS segments are no longer assumed to be separated by an intron. A CDS annotated as a ribosomal-slippage join, such as SARS-CoV-2 ORF1ab (`join(266..13468,13468..21555)`), has segments that abut or overlap and is one continuous reading frame, but its boundary was treated as an exon-exon junction: plain coding bases beside it were annotated `splice_donor_variant` / `splice_acceptor_variant` (`HIGH`) or `splice_region_variant`, escalating the impact of ordinary missense and synonymous calls, and unspliced transcripts were given NMD predictions. Only segment pairs separated by a real gap now count as junctions, for both splice terms and the 50-nucleotide NMD rule; when a slippage join follows a genuine intron, the last junction stays at that intron.
- **Scientific**: `--report-from` no longer merges distinct samples. Sample labels were taken from the file name alone, so the standard per-sample layout (`results/<sample>/variants.MNV.tsv`) interned one shared label and collapsed every input into a single row of the report matrix, silently under-reporting the cohort. Colliding inputs are now qualified with as many parent directories as it takes to tell them apart, and the chosen label is logged per file.
- `--report-from` now reports a compressed input as such instead of failing with `invalid UTF-8 in field 0 near byte index 1`; the report reads plain get_MNV TSV files.
- Protein-level insertions now use residue-aware HGVS notation naming both flanking residues (e.g. `Lys2_Phe3insGly`), matching the `del` / `delins` forms, instead of the bare-position `2_3insGly`. Insertions at the protein N- or C-terminus, which have no flanking residue on one side, keep the bare-position form.
- **Scientific**: `--split-multiallelic` no longer silently drops alternate ALT alleles when two or more alts share the same codon position. Each alt now produces an independent annotation row with its own AA effect, codon, and BAM-derived read support; true duplicates (same position + same alt) still collapse to one row.
- VCF output INFO values (`GENE`, `AA`, `CT`, `TYPE`, `EC`, `COMP`) are now percent-encoded for the structurally reserved characters (`;`, `=`, `,`, `%`, and tab/newline/CR), so GFF gene names containing those characters can no longer corrupt the INFO column or spawn bogus keys.
- `--keep-original-info` now subsets per-allele (`Number=A/R/G`) INFO fields to the split allele when a multiallelic record is divided, instead of copying the whole array onto each single-ALT output record (which produced a cardinality-invalid VCF that `bcftools` rejects).
- The BAM is now validated up front (exists, is coordinate-sorted/indexed, header readable) before any output file is created, so a missing index fails fast with an actionable message instead of erroring lazily inside a worker thread after partial output was already written.
- Output is now transactional: if a run errors after the output files are created, the partial `.MNV.tsv` / `.MNV.vcf` / BCF files are removed on exit so downstream tooling never consumes a truncated file.
- BAM region queries are now built with the structured noodles `Region` API instead of a `chrom:start-end` string, so contig names containing `:` (e.g. HLA allele contigs) are queried at the correct coordinates instead of being misparsed.
- The BGZF VCF parser now rejects `POS=0` and a missing `#CHROM` header line, matching the plain-text fast parser so both code paths validate inputs identically.
- When `--gff-features` is not specified and the GFF contains `CDS` features, get_mnv now analyses `CDS` (phase- and splice-aware) automatically instead of whole-gene spans, so eukaryotic/multi-exon annotations are no longer silently mis-numbered over introns. Passing `--gff-features gene` keeps the previous whole-gene behaviour (and still emits the CDS-phase-ignored warning).
- In a spliced transcript (CDS) model, an indel falling in an intron is no longer merged into a phased coding haplotype with nearby exonic SNVs; only exonic variants participate in coding haplotype phasing.
- A variant lying downstream of a premature stop introduced by an upstream frameshift is no longer labelled `(fs)` as if it were translated; it is reported with Change Type `Downstream of premature stop`. Applies only when a single upstream frameshift indel introduces a stop earlier than the natural one; ordinary frameshift propagation (no early stop) is unchanged.
- Resolved the frontend security audit by updating vulnerable transitive packages, including `brace-expansion` 5.0.6.
- Regenerated the Rust lockfile so vulnerable `rand` package entries are no longer present in the resolved dependency graph.
- Corrected CLI, GUI, and documentation wording for BCF input, BAM base-quality filtering, strand-bias INFO tags, and MNV rows that overlap indels.
- VCF records that already encode an MNV as a multi-base `REF/ALT` allele are now decomposed into codon-level haplotypes instead of being treated as generic indels.
- Deletions whose VCF anchor falls just outside a CDS/gene feature now still apply the overlapping deleted bases to the feature sequence, preserving frameshift/in-frame protein effects instead of reporting `Unknown`.
- Insertions anchored at the final base of a CDS/gene feature are no longer treated as if the inserted sequence were inside that feature, and boundary-spanning indels are no longer duplicated as intergenic rows.
- Indel and complex alleles in coding regions now reconstruct the local alternate CDS sequence, respect strand/phase/protein offset, and report in-frame or frameshift protein effects instead of leaving amino-acid changes blank.
- Codons split across neighbouring CDS exons can now produce a single transcript-level MNV annotation when the selected GFF/GTF `CDS` records provide a usable transcript model.
- BAM support for indels is now counted from the CIGAR-derived observed allele across the event span, including inserted sequence and deleted reference bases; exact complex haplotypes now also require the expected insertion/deletion components in the read CIGAR so net-neutral indel complexes are not mistaken for simple MNVs.
- Phased `complex_indel` rows now preserve the original event component coordinates from the input variants, so ambiguous repeat-context deletions remain consistent with the source VCF/iVar event and the original indel row.

### Changed

- **Scientific**: in a multi-sample VCF, each sample is now annotated for the alleles its own genotype carries. A record lists every ALT seen at that site across the cohort, and the parser kept all of them for whichever sample was selected, so every sample carried every variant: a sample whose genotype reads `0/0` got a call, and two adjacent substitutions merged into an MNV for a sample that had only one of them. The cohort matrix of a `--sample all` report was therefore wrong for any multi-sample input, which is the case the feature exists for. The selected sample's `GT` now decides carriage, keeping the allele when the genotype is absent or a no-call (`./.`), since unknown is not absence. On a multiallelic record `1/1` carries only the first ALT and `1/2` carries both. The count of skipped alleles is logged, and Troubleshooting explains why a run can now report fewer rows than the VCF has records.
- A sample carrying nothing writes an empty output file instead of aborting the whole cohort. Failing there stopped a `--sample all` run on the first clean sample, so every sample after it was never written. A file with no records at all is still an error, since there is a difference between nothing to annotate and nothing to read.
- A `--sample all` run whose samples would share an output file name now stops and names them both, instead of letting one overwrite the other. Each sample writes to a file named after it with the characters a file name cannot hold replaced, so a repeated header name, or a pair like `a/b` and `a_b`, resolved to one file and left a cohort silently short one member. A caller-supplied output prefix also keeps the per-sample suffix, which it was dropping.

### Fixed

- **Scientific**: a multi-base substitution outside every gene now reaches the VCF whole. The row carries one entry per changed base and the writer read only the first, so the second base of a two-base substitution appeared in the TSV and nowhere in the VCF: two outputs of one run disagreeing about what had been called.
- **Scientific**: an intergenic row is judged in the VCF the way the TSV judges it. A multi-base substitution was filtered on its SNP support, which is zero by construction when every read carries the whole haplotype, so a threshold deleted it from the VCF while the TSV kept it at 12 of 20 reads; an intergenic indel was filtered against a hardcoded support of 0 over a depth of 0 even though the same line wrote `ER=20` and `EFREQ=1.0000`. Both now use the haplotype support the TSV uses, and carry it in the INFO.
- **Scientific**: a declared phase is matched to the change it was made about. An insertion is anchored at the base it follows and its component carries the inserted sequence, so the record `28 G>GT` yields the same component as the SNV `28 G>T` and lent it its `GT`/`PS`: a codon row claimed a haplotype the input never placed it on, was flagged as contradicted by the reads, and which record came first in the file decided the answer. The claim is also read for rows the per-gene path does not build, so an MNP one base outside a gene keeps the phase an identical MNP inside it reported.
- **Scientific**: a premature stop is compared in the numbering of the rows it judges. The stop is found by translating the alternate CDS, so it arrives as a residue of the mutant protein, and it was compared against reference codon numbers, twice over: once because the indel's length change was never undone, and once because a transcript whose first CDS row declares a phase numbers its rows from `protein_offset`. A 31 nt deletion put the stop at mutant residue 9 while the rows it judged were numbered from reference codon 19, so ten codons the mutant protein still translates were reported as untranslated and `MODIFIER`. A separate gate compared the two stops by their index in proteins of different length, so a frameshift insertion of 289 bases pushed the mutant's own stop past the reference protein's last residue and was called not premature while the mutant in fact terminates near the start of the gene.
- **Scientific**: an NMD verdict is given only where a stop is actually premature. The alternate protein's first stop was compared with the reference's by index, in proteins of different length, so every in-frame deletion in a spliced transcript was called premature and published an NMD prediction beside its own `inframe_deletion` term, while a stop a large in-frame insertion genuinely introduced got no prediction at all.
- **Scientific**: the bases a declared phase skips count towards an indel's length. A phase of 2 says the first two bases of the CDS row belong to a codon that began in a neighbouring exon: they code, they just cannot be translated from this row alone. Measuring the length change over the phase-trimmed window counted a deletion of three coding bases as two, so the record was reported as a frameshift and dragged `(fs)` onto every downstream codon of the feature, where `bcftools csq` calls the same substitution a plain missense. A row whose indel reaches into those bases now says the residues are unknown rather than describing a change the trimmed window invented.
- **Scientific**: a splice site is called from the bases a record changes, not the base it starts on. A record padded with reference bases on its left begins on a base it leaves alone, so a padded record destroying a splice donor was called intergenic and deleted by `--exclude-intergenic`, and a deletion removing both essential donor bases was reported as a low-impact splice region while substituting either one of them was reported `HIGH`. The most severe consequence among the changed bases now wins.
- **Scientific**: a record straddling a gene's edge is annotated once, and only where it is. The fallback ran for any record no gene fully covered and rebuilt the whole record, so a three-base substitution on a gene ending at 75 produced a second row repeating the two coding bases with a contradictory `Unknown` call, and named that gene for the base lying past its end. Both rows survived `--exclude-intergenic`. Each base is now classified on its own and the row is built per group.
- **Scientific**: the documented insertion boundary rule applies in both annotation models, and reads the right way round on the minus strand. An insertion places its bases after its anchor, so anchored at a codon's last base it sits between that codon and the next and leaves both intact; the spliced-transcript path used the anchor's own offset and blanked the codon's substitution row to `Indel overlap`, demoting a `HIGH` `start_lost` to `MODIFIER` when the only difference between two inputs was a `Parent` attribute. On the minus strand, where the transcript reads from higher coordinates down, both that rule and the test for what lies upstream were mirrored: a deletion anchored on a codon's last genomic base removes bases that precede that codon and its frame shift did not reach it, and an insertion anchored on its first genomic base blanked a codon it never entered.
- **Scientific**: a gene keeps its own account of a base another gene also annotates. Once one gene emitted a coding row, every other gene's view of that base was lost: an overlapping gene's `splice_donor_variant` (`HIGH`) disappeared, and so did the `intron_variant` of a gene whose intron holds the base, so a run naming several genes reported fewer rows for one of them than a run naming it alone. A gene that contains the base without being able to build a codon around it lost its row the same way. Each gene is asked for itself, keyed on the consequence it states rather than on its name, since a GFF gives every transcript of a gene the same `Name` and one transcript's row was suppressing another's.
- **Scientific**: an indel reaches both codons of a base a ribosomal-slippage join reads twice. That base sits at two transcript offsets and belongs to two codons; substitutions were taught to use both, indels were still asking for the first, so a deletion of the shared base left the second codon believing nothing had happened to it and its substitution row named a residue for a codon that is no longer whole.
- **Scientific**: an in-frame indel that leaves the made protein unchanged is reported as such. An insertion inside a gene's terminal stop codon that keeps a stop there was reported as a residue inserted one position past the protein's last one, at `MODERATE` impact, on a row whose own reference and alternate codons were both a stop, while the substitution producing that very same stop codon was correctly called synonymous. The comparison ran past the stop, where nothing is translated; the whole translation still answers stop gained and stop lost, whose evidence is the count of stops.
- **Scientific**: a strand counts for a haplotype only when a read on it saw the whole of it. A fragment whose forward mate covers an insertion and whose reverse mate starts past it establishes the haplotype from the forward side alone, but both strands were credited, so a composite row reported 20 reverse reads for an insertion no reverse read ever observed and survived `--min-mnv-strand` while the plain insertion row, counted per record under the same rule, was dropped for having none.
- **Scientific**: the requested translation table reaches the stop rules, and a table-blind translation helper beside the table-aware one is deprecated. It has no callers, and any future call site would silently answer as if the run were table 11 whatever `--translation-table` says.
- **Scientific**: a gene name can no longer break the TSV it is written into. GFF3 percent-encodes its attribute values, so a gene named `gene%09tab` in the file arrives holding a real tab and `gene%0Aline` a real newline, and both were written raw: the tab put one more field on the row than the header has, shifting every column after the gene, and the newline split one variant across two lines so the file claimed a row that does not exist. The VCF writer was hardened against exactly this and its sibling was not; TSV cells now carry the same encoding, so the two outputs spell an awkward name the same way.
- The report's variant matrix keeps every gene of a site. Two overlapping genes each get a row of their own in the table, and the matrix labelled a site with the gene of whichever row reached it first, so the second gene had no bar in the gene track and could not be found by the matrix search, and which of the two survived changed when the table was sorted. The bar order and the gene list a tooltip reads are sorted so neither follows the table.
- The desktop app keeps the chosen output formats when a preset is applied. A preset sets analysis thresholds; which files to write is not one of those, and it sits beside the output directory and the compression flag, which the form already preserved. Resetting the formats while preserving `vcfGz` left a run with "compress the VCF" switched on and no VCF to compress, and a user who had asked for VCF output got a TSV instead without being told.
- The report's matrix keeps its marks inside the plot. A group tick marks the bases one row calls together, and it was drawn straight from the coordinate mapping without the clamp its neighbouring gene bars already had: zooming until the window edge fell between the two bases of an MNV drew the tick over the sample names beside the plot, by as many pixels as the zoom made a base wide.
- A matrix cell sits on the base it stands for. The gap that separates neighbouring cells was taken off the right side alone, so every mark was drawn a quarter of a pixel from its own coordinate; it is now taken off both sides.
- The report's region box no longer answers about a contig you did not name. Typing `chr2:150-250` into a report that has no `chr2` dropped the name and kept the coordinates, so the window moved to 150-250 on whatever contig was already on screen and looked exactly like the region asked for. An unknown name is now reported and the view stays where it was, as an unknown gene name already was.
- **Scientific**: the report's haplotype panel no longer merges two haplotypes from different contigs. It grouped by gene, positions and alternate bases, leaving out the contig that the matrix beside it already keys its sites by. A gene name repeats across replicons, an IS or a transposase most of all, so the same codon MNV on a chromosome and on a plasmid came out as one row labelled with one of the two contigs, with the samples of both pooled into its recurrence count and the other haplotype missing from the panel entirely.
- The desktop app warns before overwriting a cohort's outputs, and shows where they go. With `--sample all` the run writes one file set per sample, so the app previews a pattern rather than naming files whose sample list it has not read. That pattern was then handed to the overwrite check, which asked whether it exists as a file: it never does, so a cohort run reported nothing in the way while the previous run's per-sample outputs sat in the very directory chosen, and were overwritten without a word. The check now looks for the files themselves, counting only the formats the run will write. The pattern also left out the output directory, so it pointed somewhere the files were never going to land.
- The two example scripts run from a clean checkout, and stop writing into the bundled data. `reproduce_example_run.sh` required `example/G35894.bam` and `example/MTB_ancestor.gff3`, neither of which is part of the bundle, so the command the documentation gives stopped on the first line with `Missing required file`. It now takes the demo BAM that does ship, treats read evidence as optional and says when it is running without it, and falls back to the plain TSV annotation beside the GFF3 as its sibling already did. `run_example_with_bam.sh` computed the repository root as `scripts/` itself, so it looked for the binary and the data one directory too deep and reported a missing binary that was built, and it pointed at three files that have never been in the bundle. It also ran with the example directory as its working directory, which writes the output beside the committed reference TSV and over it; both scripts now write to a directory of their own.
- The example report shipped with the documentation was regenerated. It dated from before this release's report work and from before a field was added to the row schema, so the page in `docs/assets` was not the page this version produces.
- **Scientific**: a left-padded insertion is described by the codon it changes. Outside the transcript model, the codon shown for an indel was taken from the record's own reference span. That span is the first deleted base for a deletion and agrees with the event, but for an insertion it is the padding: `102 TAA>TAAG` and `104 A>AG` are the same insertion after base 104, and the first begins two bases earlier. The padded spelling therefore reported the codon before the one it changes, a codon the insertion leaves alone, on a row whose own `Event Components`, `HGVS g.` and amino-acid columns all named the right one; on the bundled annotation it printed `GCT`/`GCT`, an alternate codon identical to the reference, for a row labelled a frameshift. The codon now comes from the event's own components, which is the ruler the transcript path already used, so the two spellings agree and the row agrees with itself. `Positions`, `Reference Bases` and `Base Changes` still echo the record as documented, and `--normalize-alleles` still trims them.
- **Scientific**: the desktop app no longer pairs a sample with another sample's reads. Dropping several variant files and several BAMs matched them by name through a ladder of exact stem, prefix, then shared sample id, taking each variant file in turn and giving it the best BAM still free. Order decided, not strength: with `A.x.vcf` and `A.y.vcf` beside `A.y.bam` and `A.z.bam`, the first file took `A.y.bam` on the weakest rung, and `A.y.vcf`, which answers to it exactly, was left with `A.z.bam`. Both samples were then counted against another sample's molecules, which is every read count, frequency, strand arm, phasing ratio and linkage value in the run, with nothing on screen to say so. Pairing is now decided across the whole set, strongest match first, and a variant file with several equally good candidates is left unpaired rather than given the first one: the order files arrive in says nothing about whose reads they are. The sample list also names the BAM each sample was paired with, instead of only saying that there is one.
- The desktop app's variant table sorts its numeric columns by number. Which columns held numbers was decided by looking for "reads", "frequencies" or "positions" in the header, and `Grantham` contains none of them, so it was sorted as text: on the bundled example that orders it `10, 101, 102, 103, 107, ...` instead of `5, 10, 14, 21, ...`, putting a moderately radical substitution below a conservative one. The same words decided which columns get a dropdown filter and which are right-aligned, so the column was also filtered and laid out as if it held names. A column is now judged by its values rather than by words in its title, which covers every numeric column the tool writes rather than the three that happened to be listed. An absent value is no longer read as a zero either: `-` sorts before every real number, where the HTML report's own table already puts it, instead of being mixed in among the rows whose answer really is zero.
- **Scientific**: the desktop app's read viewer reads a BAM that carries no base qualities. SAM writes `QUAL=*` when the per-base qualities were not recorded, which is legal and which some pipelines do to save space, and the counting core says in as many words that such a base passes, for the same reason a missing MAPQ is 255. The viewer read the absence as a quality of zero instead, so every base of such a BAM failed the run's own quality floor: it drew every read blank and called every one of them uninformative, while the table beside it counted those same reads as support. One product, two answers about the same molecules.
- **Scientific**: an insertion the desktop app's read viewer cannot read is no longer counted as evidence for the reference. The viewer applies the run's own base-quality floor, and a rejected base in a match leaves the position unknown, so the read withdraws from the judgement; in an insertion the rejected base was simply dropped instead, shortening the allele the read carries. A read whose whole insertion fell below the floor came out holding none at all, which is what a read without the insertion looks like, and it was counted as supporting the reference. The three cases now give three answers: a readable insertion supports the variant, no insertion supports the reference, and an insertion that cannot be read says nothing either way.
- **Scientific**: the desktop app's read viewer tells a deleted base from one the read never reached. A CIGAR `D` and a CIGAR `N` were both drawn as a gap and both fed into the support call, but they say opposite things: `D` is the read stating those reference bases are not in it, and `N` is the read not being there at all, which is what an aligner writes for an intron. get_MNV builds spliced CDS models, so such alignments reach this viewer, and a read that skipped a deleted stretch was counted as carrying the deletion it never observed. A skipped stretch now leaves those positions unset, which the viewer already draws as empty and the support call already reads as no evidence. The layout builder is now exercised on a real record, from a one-read BAM the test writes and reads back, rather than on maps written by hand.
- **Scientific**: the desktop app's read viewer no longer invents reference bases. Its FASTA reader answered a window with `N` for every base it could not supply, so a file that no longer matches its `.fai`, a truncated copy or an index built against a different assembly, read as a contig that genuinely holds unknown bases there, with every read shown against a reference that is not the one on disk. A file shorter than its index now says so and names the rebuild command. The window is also read to the end of its span rather than keeping whatever one read call returns, since a short read is not a short file, and it stops at the next record header so the padding that covers line breaks can never let the following contig stand in for this one.
- The report's "Genes with a call" tile counts a gene per contig. It counted distinct gene names, so a report covering a chromosome and its plasmid claimed one gene where the same run's log said two. The log counts genes per contig and adds those up, and a gene spread over several exons counts once in both, which is the measure the tile now uses.

### Added

- **Pipeline-level invariants over generated inputs** (`tests/property_pipeline.rs`, run by the existing Rust CI job). The example-based tests say what the output should be for inputs somebody thought of; these say what has to hold for any input, and they are aimed at the shape almost every defect above had, which was not one wrong answer but two answers to the same question. Padding a record with reference bases does not change what it says; the order of the records does not change the output; one gene spelled as a TSV, as a GFF row and as that row with a `Parent` annotates the same, on either strand; a cohort run says about each sample what naming that sample alone says, and obeys the genotypes; several genes annotated together say about each what naming it alone says; an iVar table and the VCF that says the same thing annotate the same; and the report shows the rows the TSV of the same run holds. The generator covers records that pad, MNPs, indels, a gene with an intron, a donor and an acceptor, both strands, sites on the first and last coding base, and several changes inside one codon. Two of the fixes above were found by these on their first run. A ninth property sweeps the same padding invariance over insertions and deletions, which the first only ever exercised on substitutions, and the row summary the properties compare now includes the codon columns: leaving them out let a padded insertion name a codon it does not touch while every other column agreed.
- **Behaviour checks for the JavaScript and TypeScript the project ships** (`tests/js/run.mjs`, new CI job). The report's table, filters and matrix are built in the page and the desktop form merges a preset in the browser, so neither could be reached from the Rust suites and both were guarded by tests that read the source and checked a shape was still there, which catches a deletion and nothing else. The runner generates a cohort report with two overlapping genes, then exercises the page's own filter, search, sort and matrix functions against the TSVs of the same run, and evaluates the form's own preset merge over the shipped defaults and presets. No test framework and no new dependencies: node, the shipped sources, and a report it builds itself. Reintroducing either of the two defects above makes it fail with the values that differ. It also runs the page's drawing against a canvas that records the rectangles instead of painting them and honours the clip, so what the matrix puts on screen can be checked: no track is drawn outside the plot, every cell sits on exactly one site, and every pixel of a cell answers the mouse with that same cell. Each cell is anchored to where the coordinate mapping put it rather than to what the hit test says about its own centre, because a hit test asked to agree with itself passes just as happily when it measures the wrong span. The density lanes are counted back against the bases the TSVs hold, and the fixture carries an MNV and a deletion so no lane agrees by counting nothing on both sides.
- The scenario suite gained the splice terms and the `--exclude-intergenic` scope it had never exercised, and every scenario now writes the VCF as well and checks that the two outputs of its own run do not lose a base to each other.
- A glossary page, in English and Spanish, defining the vocabulary the rest of the documentation leans on, and the home page now writes out in text the worked example that only the figure carried, with a table of what each step of a run reads and produces.

## [1.1.2] - 2026-04-08

### Fixed
- **GFF phase (column 8) is now honoured for CDS features.** Previously, the parser read all nine GFF fields but silently dropped the phase column, so codon boundaries were computed as if every CDS started in frame 0. For eukaryotic annotations where exons begin at non-zero phase (e.g. GRCh38 Ensembl `GNAQ` CDS with `phase=1`), this caused SNVs to be grouped into the wrong codons on both strands. The GFF parser now reads column 8 (`0`, `1`, `2`, or `.`), stores it in `Gene`, and `codon_bounds_for_position` applies the offset from `gene.start` (plus strand) or `gene.end` (minus strand). TSV gene files and non-CDS features default to `phase = 0`, preserving previous behaviour. Fixes [#12](https://github.com/PathoGenOmics-Lab/get_MNV/issues/12).

### Added
- Regression tests for phase handling on both strands, including the GNAQ case from issue #12.
- TSV gene annotation files now accept an **optional 5th column** with the phase (`0`, `1`, `2` or `.`). When omitted, phase defaults to `0`, preserving the historical 4-column prokaryote-style format. 4- and 5-column rows can be mixed in the same file.
- Documentation: `docs/input-formats.md` describes the GFF phase handling and the new optional TSV phase column.
- **Two new TSV columns: `Local AA Changes` and `Local SNP AA Changes`** which carry the per-feature (exon-local) amino-acid numbering used by versions ≤ 1.1.1, alongside the new full-protein numbering in `AA Changes` / `SNP AA Changes`. For prokaryotes and single-exon features the local columns are identical to the protein columns; for multi-exon eukaryotic CDS the two pairs differ (e.g. GNAQ exon 5: `Met227Ser` vs `Met25Ser`). This lets downstream pipelines that depended on the old numbering keep working without giving up the VEP-compatible reporting.

### Changed
- **Protein amino-acid numbering is now transcript-aware for multi-exon eukaryotic CDS.** Previously, each CDS row in the GFF was treated as an independent feature and the amino-acid position of an MNV was computed locally to that exon (so a variant in GNAQ exon 5 would be reported as `Met25` even though the actual protein residue is `Met224`). The GFF parser now groups CDS rows by `transcript_id` (falling back to `Parent`), sorts the exons in transcript order (ascending for plus strand, descending for minus strand), and assigns each exon a cumulative `protein_offset` equal to the number of complete codons contributed by all prior exons of the same transcript. The final amino-acid position is `protein_offset + local_codon_index + 1`, matching the numbering used by ANNOVAR, SnpEff, Ensembl VEP, and UniProt. Prokaryotic inputs (TSV gene files or single-feature GFFs) are unaffected — `protein_offset` defaults to 0.
- **Warning when `--gff-features` does not include `CDS` but the GFF contains CDS rows with non-zero phase.** In that configuration the phase-aware codon grouping is silently disabled, which was the exact trap reported in issue #12. A single `WARN` log line now tells the user to re-run with `--gff-features CDS` so the phase information is honoured.
- **Gene name extraction from GFF attributes** is smarter for eukaryotic GTF/GFF3 files. `gene_name_from_gff` now prefers `gene_name` (GTF/Ensembl/GENCODE) and `gene_id` in addition to the existing `gene` / `Name` / `locus_tag` / `ID` fallbacks, so a GNAQ CDS row with `gene_name=GNAQ;ID=agat-cds-37838` now shows up as `GNAQ` in the TSV instead of `agat-cds-37838_agat-cds-37838`.
- When no `locus_tag` is present, the returned gene name is no longer duplicated with itself (`primary_primary`) — it is just the primary name.
