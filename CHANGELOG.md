# Changelog

All notable changes to this project are documented in this file.

## [1.1.5] - 2026-06-09

### Added
- **Interactive HTML report.** New `--report <FILE.html>` writes a single self-contained page for exploring the called variants: a headline count with supporting tiles, the Sequence Ontology consequence distribution, an alignment-style variant matrix, a read-backed haplotype panel, and a virtualised, sortable table with a filter on every column (checkbox lists for the categorical fields, contains matches for the free-text ones, min/max ranges for Grantham and frequency) and a per-variant detail panel (HGVS `g.`/`c.`/`p.`, Grantham, DBS class, NMD, codons, event components, read support). The matrix is a small genome browser: samples down the side, real genomic coordinates across the top, coloured by alternate base, with scroll-to-zoom, drag-to-pan, a whole-contig strip you can drag across to select a range, a region box that takes `start-end`, `contig:start-end`, a coordinate or a gene name, density lanes (all calls, SNP, MNV, indel, HIGH impact and distinct samples, each its own chart with its own scale), and a gene track marking the extent of each gene's called sites. It orders samples by shared profile, marks positions called together on the same reads, and zooms down to the base letter; a cell is only ever an ALT call or "not called", since get_MNV output cannot tell a reference base from missing coverage. The haplotype panel ranks codon-level MNVs and phased complex indels by how many samples share them, with their phasing support; long-range phasing is never inferred. Filters drive the charts as well as the table, the current selection can be exported as TSV, and the masthead links to the repository and the documentation. The page embeds its data and loads nothing external, so it opens offline by double-clicking; repeated fields are dictionary-encoded to keep cohort-sized reports in the low megabytes. With `--sample all` one report covers every sample. For cohorts processed one sample per run, `--report-from a.MNV.tsv b.MNV.tsv ...` aggregates existing TSV outputs into one report without re-running the pipeline.
- **Sequence Ontology consequence terms and impact levels.** New `SO Term` and `Impact` TSV columns (and `SO` / `IMPACT` VCF INFO fields) annotate every variant with a standard SO term (`missense_variant`, `synonymous_variant`, `stop_gained`, `stop_lost`, `start_lost`, `frameshift_variant`, `inframe_insertion`/`inframe_deletion`, `intergenic_variant`, `coding_sequence_variant`) and a `HIGH`/`MODERATE`/`LOW`/`MODIFIER` impact, following SnpEff/VEP conventions.
- **Grantham distance for missense changes.** A new `Grantham` TSV column (and `GD` VCF INFO field) reports the Grantham (1974) distance of the combined amino-acid substitution together with its conservation category (e.g. `177 (radical)`), for genuine missense changes only.
- **MNV-vs-SNV consequence shift.** A new `MNV Consequence Shift` TSV column (and `MNVSHIFT` VCF INFO field) flags whether a combined MNV is `MNV-gained` (more severe than any single SNV alone — e.g. two individually-synonymous SNVs producing a non-synonymous residue, which per-SNV annotators miss), `MNV-masked` (a nonsense SNV rescued by its neighbour), or `Concordant`.
- **Doublet base substitution (DBS) class.** A new `DBS Class` TSV column (and `DBS` VCF INFO field) reports the COSMIC-style doublet class for an MNV of two adjacent single-base substitutions, e.g. `CC>TT`, reverse-complement collapsed so both strands map to one class. Enables tallying mutational signatures (UV `CC>TT`, APOBEC/ADAR dinucleotide contexts) directly from codon-level MNV calls.
- **MNV phasing (linkage) support.** With `--bam`, a new `MNV Phasing Support` TSV column (and `MNVPS` VCF INFO field) answers whether the substitutions in a codon sit on the same molecules, which is the difference between a codon-level MNV and two variants that happen to share a codon. Among the reads that observe *every* position of the codon and carry the least-supported constituent SNV, it reports the fraction that also carry the full haplotype. Near `1.0` is a genuine co-occurring haplotype; low values flag same-codon SNVs that largely fall on different molecules, which matters most for intra-host data. Only reads reaching across the whole codon are counted, on either side of the ratio: one that stops between two positions saw no evidence about the pair, so it neither supports nor dilutes the answer. The three states are distinct and mean different things: a number, `0.0000` when reads did span the codon and none carried both, and `-` when nothing could answer the question. A companion `MNV Phasing Reads` column (and `MNVPR` INFO field) reports how many reads the ratio rests on, so `1.0000` from three reads is not read as `1.0000` from three hundred.
- **Phase declared by the input caller is now read and reported.** Long-read pipelines (WhatsHap, HiPhase, Clair3) publish `GT` with `|` and a `PS` phase set, resolving exactly the question get_MNV asks about a codon MNV; get_MNV ignored it, so a codon the caller had already phased arrived unannotated. Both VCF parsers now read `GT` and `PS` for the selected sample, and a new `Declared Phase` TSV column (and `DPHASE` VCF INFO field) reports what the input claimed, as `cis:12345`. Only a `|`-separated genotype counts: a `/` genotype is the caller saying it did not resolve the phase, and reading it as phase would invent linkage the input never claimed. Only records sharing a phase set are compared, since two records phased in different sets say nothing about each other, and a record is matched to a row by both coordinate and base: a multiallelic site splits into one record per ALT and a genotype such as `2|0` places the second ALT on a haplotype and the first on none, so matching on the coordinate alone would hand one allele's claim to the other. The claim is reported beside the read evidence, never merged into it, and `|contradicted-by-reads` is appended where the BAM leaves it no room: a declared cis that not one spanning read carries whole, or a declared trans that every informative read carries. Those two extremes are facts rather than judgements, so no new threshold is introduced; anything in between is already reported as a ratio by `MNV Phasing Support`.
- **Codon-level linkage disequilibrium.** With `--bam`, new `Codon LD` and `Codon LD p` TSV columns (and `LD` / `LDP` VCF INFO fields) report `D'` between a codon's substitutions and the two-tailed Fisher exact p-value behind it, computed over the molecules that observe every position. A co-occurrence ratio, which is what every phasing metric here was until now, cannot separate a haplotype from an accident of frequency: two substitutions each present on 90% of molecules are found together on 81% of them by arithmetic alone, and the ratio reports `0.9000`, which reads as strong linkage. `D'` measures the excess over what the two frequencies predict, normalised by the most that excess could have been, so the same data gives `0.0000` at `p = 1`. The scale is symmetric and that matters: `+1` is one haplotype, `~0` is two variants that merely share a codon, and `-1` is mutual exclusion, both alleles present and never on one molecule, which in a haploid population is two competing lineages rather than one variant and is the read-level signature of a mixed infection. No per-variant annotator reports this, because none of them looks at which molecules carry what; get_MNV already had the 2x2 table of molecule counts and was throwing away everything except one ratio of it. With three substitutions the weakest pair decides, since a codon-level MNV claims one molecule carries all of them. The value is absent, not zero, when no molecule spans the codon or when an allele is on every molecule or none, which leaves nothing to correlate. Validated in `tests/phasing/` against a second derivation of `D'` and of the exact test written in the suite itself.
- **Read-level phasing validation** (`tests/phasing/`, new CI job). The synthetic truth suite validates the codon arithmetic but has no BAM, so nothing checked the other half of an MNV call. This suite builds alignments molecule by molecule, choosing which reads carry which variants, and checks that get_MNV recovers the mixture it was handed; every expectation is arithmetic on the molecule counts, never a number copied from a previous run. It sweeps four codon geometries (plus strand, minus strand, a codon split by an intron and spanned by a CIGAR `N`, and all three positions of one codon) through all 21 mixtures from fully trans to fully cis, and adds the cases where the honest answer is not a number: reads that stop before the partner position, no spanning read at all, and a minority haplotype nested inside a major variant. 88 mixtures, a few seconds. Pointed at the build before the phasing fix it reports 171 disagreements.
- **Nonsense-mediated decay (NMD) prediction.** A new `NMD Prediction` TSV column (and `NMD` VCF INFO field) applies the 50-nucleotide rule to premature stops in multi-exon transcripts: `NMD-triggering` when the premature stop is more than 50 nt upstream of the last exon-exon junction, `NMD-escaping` when it lies in the last exon or within 50 nt of that junction. Covers nonsense SNVs/MNVs and stop-gaining indels (frameshift and in-frame); single-exon transcripts have no junction and are left unannotated.
- **HGVS genomic and coding descriptors.** New `HGVS g.` and `HGVS c.` TSV columns (and `HGVSG` / `HGVSC` VCF INFO fields) complement the existing protein-level (`p.`) notation. Genomic descriptors cover every variant: `g.100A>G` for SNVs, the allele bracket `g.[28G>T;30T>A]` for MNVs, and `g.101_102del` / `g.100_101insTG` / `g.101delinsC` for indels. Coding descriptors cover substitutions (`c.30A>G`, `c.[28G>A;30T>C]`), numbered from the CDS start with coding-strand bases on both strands. Descriptors are not 3'-shifted and carry no reference-accession prefix; coding indel descriptors are not yet emitted.
- **Splice-site consequence terms.** Variants near an internal exon-exon junction of a multi-exon transcript now receive the standard Sequence Ontology splice terms in the `SO Term` / `Impact` columns (and `SO` / `IMPACT` VCF INFO fields): `splice_donor_variant` / `splice_acceptor_variant` for the two essential intronic bases at each intron end (`HIGH`), and `splice_region_variant` for the exon's last 3 bases or the intron's 3rd-8th bases (`LOW`). Intronic splice variants, previously reported as intergenic, are now associated with their gene; an exonic coding change near a junction is combined, e.g. `missense_variant&splice_region_variant`, keeping the more severe impact. Single-exon transcripts (prokaryotes, most viruses) have no junction and are unaffected, as are CDS models whose segments abut or overlap in a ribosomal-slippage join rather than being spliced.
- **Synthetic ground-truth validation** (`tests/truth/`, new CI job). The differential suite compares against tools we did not write, which is the stronger check, but it cannot validate the one thing get_MNV exists for: no per-variant annotator combines two SNVs in a codon the way get_MNV does, so on exactly those calls the oracles disagree by design. This suite builds a genome with four genes (plus and minus strand, single-exon and spliced) and derives the expected answer by a different route from get_MNV's: mutate the genome, re-extract the CDS, translate, compare proteins, using a codon table written out in the suite. It covers every single substitution at every position of every codon, every pair in a codon, and the triple, plus 2130 indels (deletions and insertions of 1 to 3 bases at every position of every exon, with the indel applied in CDS coordinate space): about 3700 cases, each checked on gene, amino-acid change, change type, both codons and the HGVS `c.` descriptor, in about twelve seconds. It is a second implementation by the same hand, so it catches implementation mistakes rather than a shared misunderstanding, and the consequence labels follow the documented convention; the amino acid, the codons and the CDS coordinate are the independent parts. Pointed at the build before the codon-orientation fix it reports 240 disagreements, all on the minus-strand genes.
- **Differential annotation suite** (`tests/differential/`, new CI job). get_MNV's own tests can only check that it produces what we wrote down as expected; when the expectation is wrong the test goes green and the tool stays wrong, which is how a ribosomal-slippage CDS join came to be given splice sites. The suite compares get_MNV against annotators we did not write: `bcftools csq` run live on small committed fixtures (a slippage join and, as the positive control, a genuinely spliced transcript), both tools reading the same reference and the same GFF3; and SnpEff 4.1l through the `ANN=` fields already present in the bundled *M. tuberculosis* VCF, where 923 of 950 real calls agree. The rule is not that the tools must match, because get_MNV disagrees on purpose: every difference is matched against `baseline.tsv`, a versioned list of accepted differences with the reason written down, and CI fails only on a difference nobody has explained. `GET_MNV_BIN` points the suite at another build, which is how it was confirmed to still fail on the commit before the slippage fix.
- Added regression coverage for phased MNV-plus-indel haplotypes, verifying that codon MNV rows overlapping an indel are flagged as `Indel overlap` while BAM-supported combined events are emitted as exact `complex_indel` rows.
- Added an indel/MNV semantics note documenting caller compatibility, boundary rules, current limits, and how exact complex haplotypes are represented.
- Added transcript-aware regression coverage for exon-junction MNV codons and restored-frame indel contexts in multi-exon CDS models.

### Changed
- Added mutation testing (`cargo mutants`, `.cargo/mutants.toml`, a scheduled advisory CI job). It changes the source (flips a comparison, replaces a function body with a default) and reports whether the suite notices; a surviving mutant is logic no test distinguishes. Its first run showed that the indel and frameshift-propagation conditionals of the **spliced-transcript** path were almost entirely undistinguished: the scenario suite covers that logic on single-feature prokaryotic genes, which take the genomic-coordinate path, and the spliced path has its own copy. Five tests now cover it (upstream frameshift reaching the next exon, an in-frame upstream indel not shifting anything, no propagation backwards, an indel marking only the codon it overlaps, and the frequency gate), and they kill five of the six mutants that survived there; the sixth is equivalent, since only `% 3 != 0` is read and that cannot tell a sign flip apart. It also found a redundant guard in the stop-count comparison, now removed. The job never fails the build.
### Changed
- A paired-end fragment now counts as one molecule instead of two reads. A fragment is a single DNA molecule sequenced from both ends, and get_MNV was counting its two mates as two independent observations. That did two kinds of damage. Wherever the mates overlap, the same molecule was counted twice, inflating depth and making a frequency look supported by twice the material actually there. And a variant on each mate was treated as unrelated when it is in fact proof the two are on the same molecule: a codon split by an intron can be unanswerable read by read (`MNV Phasing Support` of `-`) and settled by the pair. Read counting, local haplotype discovery, the indel/complex event counts and the indel-versus-SNV trans test now work per molecule; where the mates overlap and disagree about a base, one of them is wrong and there is no telling which, so the molecule is treated as not having observed that position. A molecule read from both ends is evidence on both strands, so it is tallied in both strand arms, as the depth counters already were: crediting it to forward alone would leave the reverse arm empty for every mate pair, which reads as total strand bias and trips `--min-snp-strand` / `--min-mnv-strand` on perfectly balanced data. The same view applies to the indel and complex-event counts: a molecule whose mates read different alleles over the locus does not support the call, where before a single mate carrying an alignment artefact was enough to credit the whole molecule, and mate overlap is exactly where indel realignment artefacts appear. Single-end data is unaffected. `--count-mates-separately` restores the per-record behaviour for comparability with earlier output. Exact event counting still needs one contiguous observation, so a local haplotype whose variants fall on different mates is discovered but cannot be supported, and the support threshold drops it rather than reporting it with no evidence.
- The read-level phasing behind frameshift suppression is now reported instead of only acted on. When a BAM is given, get_MNV already asks whether an upstream indel and a downstream codon share molecules, and declines to propagate the frame shift when they do not; the numbers behind that decision were computed and thrown away. A new `Frameshift Phasing` TSV column (and `FSPH` VCF INFO field) carries them as `trans:1234:0/18`: the verdict, the indel's position, and the reads in cis out of the reads able to answer. Without it a codon that is not labelled frameshifted looked identical whether the reads had proved the indel sits on other molecules or nobody had asked. The cis/trans thresholds stay with the read counting that applies them, so the annotation layer reports a judged answer rather than re-deriving the rule from the counts.
- `--phased-indel-min-reads` now defaults to `2` (was `1`). Since haplotypes are read off the molecules, a single read carrying a sequencing error at a called position mints a combination of its own, and one read was enough to publish it as a haplotype row. Two reads is the least that means more than one molecule. Set `1` to emit every combination any read shows.
- Local haplotypes are now read off the molecules instead of enumerated and checked. Nearby variants were grouped into a window, every subset of that window was proposed as a candidate haplotype, and each was put to the BAM one query at a time. Two things followed. A subset was accepted whenever some read matched its compound allele over that subset's own span, so a single molecule carrying A, B and C also answered yes for A-plus-B and for B-plus-C, and one species was reported as three rows, each claiming the full read count and 100% frequency. And because `2^n` candidates is not a workable number, windows of more than eight linked variants fell back to pairs and the full set, silently omitting genuine intermediate haplotypes. get_MNV now asks the reads spanning the window which combinations they carry and reports those, with the count of molecules behind each. A combination no molecule is does not appear; two combinations that genuinely coexist both appear with their own counts, which the old scheme could not tell apart from one molecule carrying everything. The variant cap is gone, since reading costs one query per window rather than one per candidate; a bound of 64 reported combinations per window remains as a guard against a noisy pile-up, and says in the log what it set aside. A molecule that stops inside the window is counted separately and used for nothing, because a partial molecule is not a haplotype. Each candidate is judged on its own reference span, and for an insertion that span reaches one base past the anchor: an insertion lives between two reference bases, so a read ending on the anchor has seen the anchor and nothing of the junction, and recording it as evidence that the insertion is absent minted a subset haplotype no molecule had shown.
- Where a transcript's introns are is now derived once, by `Gene::introns`, instead of being recomputed by splice-site classification, the intronic-position test and the NMD junction independently. Three copies of the same geometry are three chances to disagree about it, which is the shape of the bug that gave a ribosomal-slippage join splice sites. The derivation yields nothing for an unspliced transcript, so that case is handled in one place too.
- The GFF CDS model now rejects and reports annotation it cannot assemble. A transcript whose CDS rows disagree about the strand kept whichever strand came first and sorted the segments by it, silently producing a nonsense reading frame; those rows are now left as per-feature annotations with a warning. A CDS row listed twice (concatenated annotation files, a repeated segment) counted its bases twice in the spliced CDS and shifted every codon after it; repeats are now dropped with a warning. A run that builds multi-segment models logs how many came out spliced and how many are one continuous reading frame, so the model get_MNV understood is visible rather than assumed.
### Changed
- Added property-based tests (`proptest`) over generated inputs. The headline invariant is strand symmetry: annotating a variant on a plus-strand gene must give the same amino-acid consequence, change type and codons as annotating the mirrored variant on the reverse-complemented genome, where the same gene sits on the minus strand. The two runs describe the same molecule, so every protein-level answer has to match, and no hand-written example pins that down across gene lengths, offsets and positions at once; it found the codon-orientation bug above on its first run. Codon-bounds invariants are now checked over generated gene shapes, strands and phases rather than one hard-coded feature.
### Changed
- Gene fixtures in the test suite are now built from GFF text through the real parser (`test_support`), not from hand-written `Gene` struct literals. A literal can describe a gene model no annotation file would produce, and then the test agrees with the code about something untrue: a helper named `two_exon_gene` built exons that abutted, with no intron between them, so every test meant to cover splicing was quietly asserting the behaviour of an unspliced transcript, and they passed while confirming a bug. `spliced_gene` and `joined_gene` now refuse segments that do not match the transcript the test claims to be about, so the fixture name carries the claim and the helper enforces it. 40 of the 46 literals are gone; the survivors are two parser constructors, one raw-record builder used to test the parser itself, a benchmark, and two deliberately impossible models, each marked as such. Parsing was split into a reader-based entry point so annotation can be parsed from memory. Output is unchanged: the differential suite reports the same agreements before and after.
- Consequence classification now lives in one module (`variants::consequence`) instead of two independent implementations. Substitutions were classified by `determine_change_type`, which parsed a formatted string such as `M1T`, while indels had their own rules over the reference and alternate translations; the initiator rule existed on the substitution side only, which is how an in-frame indel that deleted the start codon came to be reported at `MODERATE` impact. Both paths now call the same rules, a test holds them to the same answer for every residue at protein position 1, and the codon paths pass the residues directly instead of formatting a string for the classifier to parse back out (feeding it the three-letter IUPAC form used to misclassify the change). Output is unchanged: the differential suite reports the same 923 of 950 agreements on the real dataset before and after.
- `--chrom` now restricts FASTA loading: when a single contig is requested, only that contig is read and IUPAC-validated instead of the whole genome, cutting peak memory for large (e.g. eukaryotic) references. A missing requested contig now fails with a clear "not found in FASTA" error.
- SNVs/MNVs that alter the initiator Met (protein position 1) are now reported with Change Type `Start lost` instead of `Non-synonymous`, matching standard annotators. The reported amino-acid change was already correct; only the classification label changes. `Met1` → stop is still `Stop gained`.
- Added a tuned `[profile.release]` (thin LTO, single codegen unit) and wrapped plain (non-BGZF) VCF output in a buffered writer with an explicit flush, for faster production builds and record emission.
- Pinned `sha2` to the stable `0.10` line (previously a `0.11` pre-release), removing a duplicate hashing dependency stack from the resolved graph.
- `get_mnv_variants_for_gene` and `get_mnv_variants_for_transcript` now build a list of mutually-exclusive codon interpretations per codon start. Multi-allelic positions expand the interpretation set as a Cartesian product, deduplicated by `(position, alt)` keys, so a codon that contains N independent alts emits N output rows.
- Bumped project, GUI, citation, README, and frontend metadata to version 1.1.4.
- Updated the Tauri desktop dependency set to the 2.11 patch line, including `tauri` 2.11.2 and `tauri-plugin-dialog` 2.7.1.
- Updated frontend lockfile dependencies, including `postcss` 8.5.10.
- Added allele-level event decomposition for `snp`, `mnv`, `insertion`, `deletion`, `delins`, `complex_indel`, and symbolic alleles so length-changing events that also contain SNV/MNV components are represented as a single local haplotype event.
- Expanded phased local haplotype discovery from indel-plus-SNV pairs to bounded multi-event windows, allowing supported combinations such as insertion-plus-deletion haplotypes to be emitted as exact `complex_indel` rows.
- iVar TSV inputs now keep insertion and deletion rows by converting `+SEQ` and `-SEQ` alleles into VCF-compatible anchored `REF/ALT` alleles using the FASTA reference.
- TSV and VCF outputs now include canonical event class/component annotations plus exact BAM-derived event support metrics for indel/complex alleles.
- The desktop BAM viewer now renders insertion-aware interbase columns, so inserted bases are shown between reference positions with matching coverage, ruler, reference, and read-pileup alignment instead of being hidden inside the anchor base.
- When a BAM is provided, nearby SNV/MNV rows that phase with an indel on the same reads are now emitted as an additional exact `complex_indel` haplotype row, preserving the original rows while reporting the combined `REF/ALT`, protein effect, and event support.
- GFF/GTF `CDS` rows with `transcript_id` or `Parent` are now collapsed into spliced transcript CDS models, so codon grouping, MNV amino-acid effects, and indel frameshift context are evaluated against the full coding sequence instead of isolated exon rows.
- `--frameshift-min-freq` now defaults to `0.5` instead of `0.0`: an upstream indel only shifts the reading frame of downstream SNV/MNV codons when it is the consensus (majority) allele, so a high-frequency downstream substitution is no longer relabelled frameshifted because of a low-frequency upstream indel that is almost certainly on a different molecule (intra-host data). Indels without a known frequency still propagate. Pass `--frameshift-min-freq 0.0` for the previous behaviour.
- Frameshift propagation is now **read-phased** when a BAM is provided: for an upstream indel and a downstream SNV within a read's reach, reads spanning both loci are inspected, and the frame shift is not propagated to that codon when the reads carrying the SNV overwhelmingly lack the indel (the two are in trans, on different molecules). This is a conservative, suppression-only refinement on top of the frequency gate (it never adds propagation the gate would not), and applies only where reads span both loci; beyond a read's reach the frequency gate still governs.
- Indel locus depth (the `EDP`/`EFREQ` denominator) is now counted from reads observing the anchor base by default, removing the depth under-counting and `EFREQ` bias for multi-base deletions. Pass `--legacy-indel-depth` to restrict the denominator to reads that fully span the REF allele.

### Fixed
- The per-SNV columns of a minus-strand MNV are now emitted in ascending genomic order on both annotation paths. The spliced-transcript path listed them in transcript order (descending on the minus strand) while the genomic-coordinate path used ascending, so the same variant came out with `Positions` reversed depending on whether the annotation was a TSV or a GFF transcript, and the transcript path contradicted the `HGVS g.` descriptor on its own row, which is always ascending. `Positions` is a coordinate column; the parallel per-SNV columns follow it. The amino-acid calls were identical throughout, and the order is now documented.
### Fixed
- **Scientific**: a read that skips an intron (CIGAR `N`) is no longer counted as carrying a deletion of those bases. Both `N` and `D` advance the reference without consuming query bases, and the observed allele was reconstructed from the CIGAR treating them alike, so a spliced read looked exactly like one carrying the deletion allele: a 2 bp deletion covered only by an intron-skipping read was reported with `Event Reads = 1` and `Event Frequency = 1.0000`, perfect support from a read that does not carry it. A skipped position is now simply not observed by that read, which is what it is. `D` still means the base is absent from the molecule. Single-base lookups already treated the two alike correctly, because there both mean "no base here".
### Fixed
- **Scientific**: the codon columns (`Reference Codon`, `SNP Codon`, `MNV Codon`) are now reported in the transcript's own orientation on every annotation path. The genomic-coordinate path emitted the genomic-strand bases for a minus-strand gene, so a row could read `Reference Codon = CAT` beside `AA Changes = Met1`, a codon that does not translate to the amino acid next to it, while the spliced-transcript path and the `HGVS c.` column on the same row already used coding-strand bases. The same gene and variant therefore produced different codons depending on whether the annotation was a TSV/single-CDS file or a multi-exon GFF. Amino-acid calls, change types and impacts are unaffected. Found by the new strand-symmetry property test.
### Fixed
- **Scientific**: the TSV annotation format gained an optional sixth column for the feature biotype, so non-coding RNA genes are no longer translated as though they were proteins. The format carried no biotype at all, so every feature was assumed protein-coding and a variant in an RNA gene came back with an invented amino-acid change at `MODERATE` impact (`mcr11_RVnc0013` in the bundled *M. tuberculosis* annotation reported `Asp26Gly`). A feature declared non-coding is now reported against its gene as `non_coding_transcript_exon_variant` (`MODIFIER`) with no amino-acid change. Four- and five-column files keep their existing behaviour, and an unrecognised biotype is rejected with an error listing the accepted vocabulary rather than guessed. GFF/GTF input is unaffected, because it selects `CDS` features. Found by the differential suite.
- **Scientific**: a variant inside a real intron is now reported as `intron_variant` (`MODIFIER`) against the gene it sits in, instead of `intergenic_variant`. A position deep in an intron falls outside every CDS segment, and get_MNV had no intronic concept at all, so it was called intergenic: correct for prokaryotes, wrong for the spliced transcripts get_MNV now supports, and it dropped the gene from the annotation entirely. Splice sites keep their more specific terms, and an unspliced transcript (a single CDS segment, or a ribosomal-slippage join) has no intronic positions, so prokaryotic annotation is unchanged. Found by the new differential suite on its first run.
- **Scientific**: an in-frame indel that destroys the initiator codon is now reported as `Start lost` / `start_lost` (`HIGH`) instead of the generic `In-frame Indel` / `inframe_deletion`-`inframe_insertion` (`MODERATE`). Substitutions already reported this, so the same consequence carried two different impacts depending on the variant class, and a deletion of the start codon was invisible to anyone filtering on `HIGH`. The amino-acid notation is unchanged (`Met1del`, `Met1delinsArgVal`). Frameshifts keep the frameshift label, which is already `HIGH`, and a CDS model that does not begin at an initiator (partial or phase-shifted) is left alone.
- The report's per-column categorical filters now use a prototype-less lookup, so a value named `constructor`, `toString` or similar can no longer match an inherited property and pass a filter it was not selected in.
- **Scientific**: consecutive CDS segments are no longer assumed to be separated by an intron. A CDS annotated as a ribosomal-slippage join, such as SARS-CoV-2 ORF1ab (`join(266..13468,13468..21555)`), has segments that abut or overlap and is one continuous reading frame, but its boundary was treated as an exon-exon junction: plain coding bases beside it were annotated `splice_donor_variant` / `splice_acceptor_variant` (`HIGH`) or `splice_region_variant`, escalating the impact of ordinary missense and synonymous calls, and unspliced transcripts were given NMD predictions. Only segment pairs separated by a real gap now count as junctions, for both splice terms and the 50-nucleotide NMD rule; when a slippage join follows a genuine intron, the last junction stays at that intron.
- **Scientific**: `--report-from` no longer merges distinct samples. Sample labels were taken from the file name alone, so the standard per-sample layout (`results/<sample>/variants.MNV.tsv`) interned one shared label and collapsed every input into a single row of the report matrix, silently under-reporting the cohort. Colliding inputs are now qualified with as many parent directories as it takes to tell them apart, and the chosen label is logged per file.
- `--report-from` now reports a compressed input as such instead of failing with `invalid UTF-8 in field 0 near byte index 1`; the report reads plain get_MNV TSV files.
- Protein-level insertions now use residue-aware HGVS notation naming both flanking residues (e.g. `Lys2_Phe3insGly`), matching the `del` / `delins` forms, instead of the bare-position `2_3insGly`. Insertions at the protein N- or C-terminus, which have no flanking residue on one side, keep the bare-position form.
- **Scientific**: `--split-multiallelic` no longer silently drops alternate ALT alleles when two or more alts share the same codon position. Each alt now produces an independent annotation row with its own AA effect, codon, and BAM-derived read support; true duplicates (same position + same alt) still collapse to one row.
- VCF output INFO values (`GENE`, `AA`, `CT`, `TYPE`, `EC`, `COMP`) are now percent-encoded for the structurally reserved characters (`;`, `=`, `,`, `%`, and tab/newline/CR), so GFF gene names containing those characters can no longer corrupt the INFO column or spawn bogus keys.
- `--keep-original-info` now subsets per-allele (`Number=A/R/G`) INFO fields to the split allele when a multiallelic record is divided, instead of copying the whole array onto each single-ALT output record (which produced a cardinality-invalid VCF that `bcftools` rejects).
- The BAM is now validated up front (exists, is coordinate-sorted/indexed, header readable) before any output file is created, so a missing index fails fast with an actionable message instead of erroring lazily inside a worker thread after partial output was already written.
- Output is now transactional: if a run errors after the output files are created, the partial `.MNV.tsv` / `.MNV.vcf` / BCF files are removed on exit so downstream tooling never consumes a truncated file.
- BAM region queries are now built with the structured noodles `Region` API instead of a `chrom:start-end` string, so contig names containing `:` (e.g. HLA allele contigs) are queried at the correct coordinates instead of being misparsed.
- The BGZF VCF parser now rejects `POS=0` and a missing `#CHROM` header line, matching the plain-text fast parser so both code paths validate inputs identically.
- When `--gff-features` is not specified and the GFF contains `CDS` features, get_mnv now analyses `CDS` (phase- and splice-aware) automatically instead of whole-gene spans, so eukaryotic/multi-exon annotations are no longer silently mis-numbered over introns. Passing `--gff-features gene` keeps the previous whole-gene behaviour (and still emits the CDS-phase-ignored warning).
- In a spliced transcript (CDS) model, an indel falling in an intron is no longer merged into a phased coding haplotype with nearby exonic SNVs; only exonic variants participate in coding haplotype phasing.
- A variant lying downstream of a premature stop introduced by an upstream frameshift is no longer labelled `(fs)` as if it were translated; it is reported with Change Type `Downstream of premature stop`. Applies only when a single upstream frameshift indel introduces a stop earlier than the natural one; ordinary frameshift propagation (no early stop) is unchanged.
- Resolved the frontend security audit by updating vulnerable transitive packages, including `brace-expansion` 5.0.6.
- Regenerated the Rust lockfile so vulnerable `rand` package entries are no longer present in the resolved dependency graph.
- Corrected CLI, GUI, and documentation wording for BCF input, BAM base-quality filtering, strand-bias INFO tags, and MNV rows that overlap indels.
- VCF records that already encode an MNV as a multi-base `REF/ALT` allele are now decomposed into codon-level haplotypes instead of being treated as generic indels.
- Deletions whose VCF anchor falls just outside a CDS/gene feature now still apply the overlapping deleted bases to the feature sequence, preserving frameshift/in-frame protein effects instead of reporting `Unknown`.
- Insertions anchored at the final base of a CDS/gene feature are no longer treated as if the inserted sequence were inside that feature, and boundary-spanning indels are no longer duplicated as intergenic rows.
- Indel and complex alleles in coding regions now reconstruct the local alternate CDS sequence, respect strand/phase/protein offset, and report in-frame or frameshift protein effects instead of leaving amino-acid changes blank.
- Codons split across neighbouring CDS exons can now produce a single transcript-level MNV annotation when the selected GFF/GTF `CDS` records provide a usable transcript model.
- BAM support for indels is now counted from the CIGAR-derived observed allele across the event span, including inserted sequence and deleted reference bases; exact complex haplotypes now also require the expected insertion/deletion components in the read CIGAR so net-neutral indel complexes are not mistaken for simple MNVs.
- Phased `complex_indel` rows now preserve the original event component coordinates from the input variants, so ambiguous repeat-context deletions remain consistent with the source VCF/iVar event and the original indel row.

## [1.1.4] - 2026-06-09

### Fixed
- Intergenic variants were silently dropped under read or strand thresholds because they were never read-counted. Read counting runs gene by gene, so intergenic positions reached the output filters with a support of 0, and any positive `--snp`, `--mnv`, `--min-snp-strand`, `--min-mnv-strand`, or `--min-snp-frequency` removed them whenever a BAM was supplied (affecting the VCF since 1.1.0 and the TSV since 1.1.3). Use `--exclude-intergenic` to drop intergenic variants on purpose.

## [1.1.2] - 2026-04-08

### Fixed
- **GFF phase (column 8) is now honoured for CDS features.** Previously, the parser read all nine GFF fields but silently dropped the phase column, so codon boundaries were computed as if every CDS started in frame 0. For eukaryotic annotations where exons begin at non-zero phase (e.g. GRCh38 Ensembl `GNAQ` CDS with `phase=1`), this caused SNVs to be grouped into the wrong codons on both strands. The GFF parser now reads column 8 (`0`, `1`, `2`, or `.`), stores it in `Gene`, and `codon_bounds_for_position` applies the offset from `gene.start` (plus strand) or `gene.end` (minus strand). TSV gene files and non-CDS features default to `phase = 0`, preserving previous behaviour. Fixes [#12](https://github.com/PathoGenOmics-Lab/get_MNV/issues/12).

### Added
- Regression tests for phase handling on both strands, including the GNAQ case from issue #12.
- TSV gene annotation files now accept an **optional 5th column** with the phase (`0`, `1`, `2` or `.`). When omitted, phase defaults to `0`, preserving the historical 4-column prokaryote-style format. 4- and 5-column rows can be mixed in the same file.
- Documentation: `docs/input-formats.md` describes the GFF phase handling and the new optional TSV phase column.
- **Two new TSV columns: `Local AA Changes` and `Local SNP AA Changes`** which carry the per-feature (exon-local) amino-acid numbering used by versions ≤ 1.1.1, alongside the new full-protein numbering in `AA Changes` / `SNP AA Changes`. For prokaryotes and single-exon features the local columns are identical to the protein columns; for multi-exon eukaryotic CDS the two pairs differ (e.g. GNAQ exon 5: `Met227Ser` vs `Met25Ser`). This lets downstream pipelines that depended on the old numbering keep working without giving up the VEP-compatible reporting.

### Changed
- **Protein amino-acid numbering is now transcript-aware for multi-exon eukaryotic CDS.** Previously, each CDS row in the GFF was treated as an independent feature and the amino-acid position of an MNV was computed locally to that exon (so a variant in GNAQ exon 5 would be reported as `Met25` even though the actual protein residue is `Met224`). The GFF parser now groups CDS rows by `transcript_id` (falling back to `Parent`), sorts the exons in transcript order (ascending for plus strand, descending for minus strand), and assigns each exon a cumulative `protein_offset` equal to the number of complete codons contributed by all prior exons of the same transcript. The final amino-acid position is `protein_offset + local_codon_index + 1`, matching the numbering used by ANNOVAR, SnpEff, Ensembl VEP, and UniProt. Prokaryotic inputs (TSV gene files or single-feature GFFs) are unaffected — `protein_offset` defaults to 0.
- **Warning when `--gff-features` does not include `CDS` but the GFF contains CDS rows with non-zero phase.** In that configuration the phase-aware codon grouping is silently disabled, which was the exact trap reported in issue #12. A single `WARN` log line now tells the user to re-run with `--gff-features CDS` so the phase information is honoured.
- **Gene name extraction from GFF attributes** is smarter for eukaryotic GTF/GFF3 files. `gene_name_from_gff` now prefers `gene_name` (GTF/Ensembl/GENCODE) and `gene_id` in addition to the existing `gene` / `Name` / `locus_tag` / `ID` fallbacks, so a GNAQ CDS row with `gene_name=GNAQ;ID=agat-cds-37838` now shows up as `GNAQ` in the TSV instead of `agat-cds-37838_agat-cds-37838`.
- When no `locus_tag` is present, the returned gene name is no longer duplicated with itself (`primary_primary`) — it is just the primary name.
